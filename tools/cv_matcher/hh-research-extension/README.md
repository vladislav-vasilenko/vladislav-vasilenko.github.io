## Быстрый повторный сбор и очистка отказов — 0.11.8

Полное описание кэшируется на 24 часа в обычном и фоновом сборе HH / компаний.
Новое чтение карточки не продлевает этот срок. Признаки изменения заголовка,
компании, краткого текста или даты в выдаче помечают описание для перечитывания.
В шаге «Сбор» есть отдельная галочка принудительного обновления. Отсутствие
вакансии в выдаче само по себе не заставляет открывать её до истечения кэша.
Без открытия вакансии нельзя гарантировать, что полный текст не изменился;
перед отправкой отклика активность проверяется отдельно.

Шаг «Отклик» → «Уже отправленные отклики» → «Проверить и очистить отказы HH»:
проверка страниц в отдельной вкладке → список явных отказов → выбор → подтверждение.
До удаления отказ сохраняется в SQLite через локальный сервис. Сама история CRM
не удаляется. Предпросмотр действует 10 минут; неоднозначные или изменившиеся
карточки пропускаются. При неопределённом результате клика очистка останавливается
без автоматического повтора. Неизвестные статусы, закрытые вакансии и отсутствие
карточки не считаются отказом. Предел одной проверки — 100 страниц / 5 минут;
неполное покрытие явно показано. Если HH изменил кнопку или диалог удаления,
обработка остановится; возможность восстановления удаления на HH не подтверждена.

## Автосинхронизация HH и резюме по ссылке

После подключения HH в параметрах расширения сервис ставит задачу чтения
откликов каждые 5 минут. Расширение использует отдельную временную вкладку,
читает до 5 страниц списка и до 6 чатов за проход, чередуя чаты между проходами.
Это чтение доступной части переписки, а не гарантия полного архива HH.
Первое чтение чата сохраняет историю без рассылки старых сообщений; новые
сообщения и изменения известных статусов поступают в управляющий Telegram-бот.
Пауза и состояние — в веб-сервисе «Сегодня»; в Telegram состояние показывает `/status`.
При ошибке интервал увеличивается. Chrome, расширение и Python-сервис должны работать.

Веб-сервис → «Резюме» → «Добавить резюме по ссылке HH»: вставьте прямую ссылку
`https://hh.ru/resume/…`, затем «Добавить через Chrome». Можно добавить резюме
знакомого: наличие в вашем каталоге не требуется, но HH должен разрешать
просмотр полного текста в Chrome. Нужен доступ расширения к hh.ru, а подключение
служебной вкладки для этого импорта не обязательно. После сохранения нажмите
«Открыть сохранённое резюме». Основное CV не меняется, LLM и embeddings не вызываются.

Chrome MV3: JS читает открытые страницы, Chrome API переключает выдачу HH и
полные вакансии. Зависимости от публичного HH API / headhunter-mcp-server нет.
Рабочий сбор обходится без Playwright/Selenium. Ранжирование по явно выбранному
резюме доступно прямо из расширения через защищённый локальный OpenAI-сервис.

Полный сценарий: [инструкция соискателя](../docs/applicant_quickstart.md).

старые экспорты v1 поддерживаются с прежним приватным профилем.

## Локальный сервис

Из папки `cv_matcher`:

```sh
.venv/bin/python resume_import_server.py
```

`OPENAI_API_KEY` задаётся в локальном `.env` либо окружении сервиса.
API-ключ не передаётся расширению. Код соединения из `.cache/resume_import/token.txt`
передаётся в `X-Resume-Import-Token` только на `http://127.0.0.1:8788`.
Без него `/health`, `/extract`, `/rank` недоступны. CORS принимает extension origins.

Файлы не сохраняются сервером. DOCX разбирается локально как XML, DOC — macOS
textutil, PDF — pypdf без OCR, Pages — XML/IWA text storage с проверкой preview.
TXT/MD могут читаться прямо в расширении. Макросы и код документов не выполняются.
Для Pages со сложной структурой использовать экспорт DOCX/PDF, если текст неполон.

Рейтинг: `text-embedding-3-small` / `text-embedding-3-large`, весь текст разбивается
на фрагменты без обрезания; среднее двух самых близких JD-фрагментов к CV.
Если задана цель: 80% CV + 20% цель; иначе только CV. Начальная эвристика,
не оценка покрытия всех требований. Показаны близкие фрагменты источников.
Неподтверждённые описания/архивные вакансии исключаются. До 200 вакансий/4000
фрагментов. Кэш учитывает модель и текст; разные пространства не смешиваются.
Подробные комментарии о пробелах требуют отдельного LLM-анализа.

## Разрешения и границы

Постоянные разрешения: `activeTab`, `scripting`, `storage`.
Дополнительные по кнопке и с подтверждением в Chrome:

- `http://127.0.0.1/*` — импорт файлов/ранжирование через локальный сервис;
- `https://docs.google.com/*`, `https://*.googleusercontent.com/*` — документ
  и редирект его текстового экспорта, с Google-сессией текущего Chrome.

Код читает только Google Doc открытой вкладки по нажатию пользователя.
Ограничения экспорта владельца не обходятся. Cookies не экспортируются и не
считываются через cookies API. Ключ OpenAI остаётся на сервере, код соединения
хранится в storage.session. Хранилище вакансий/резюме локальное; удаление
расширения может удалить его, поэтому для сохранности экспортировать JSON.

Сбор не отправляет отклики, не запускается по расписанию, не решает CAPTCHA.
Popup может закрыться во время HH-обхода: прогресс хранится worker в storage.
При закрытии Chrome/вкладки результат может быть частичным. Нужно повторить запуск.
Ранжирование идёт на отдельной вкладке: её следует оставить открытой до завершения.

Новый job board: JobPosting/JSON-LD либо CSS-рецепт. `needs_review` требует
сверки с исходником; Python пропускает такие записи до подтверждения. Смена DOM,
iframe/shadow DOM и собственная пагинация сайтов требуют адаптера.
Huawei R&D — Top-Tier; [ссылки поиска Huawei](../docs/huawei_search.md).
Специальный адаптер модальных/inline описаний Huawei RRI ещё не проверен.

## Сопроводительные тексты (0.6.2)

В карточке рейтинга «Сопроводительный текст» вызывает защищённый POST /cover-letter
с одним выбранным CV и одной полной вакансией. API-ключ остаётся в сервисе.
В настройках карточки можно добавить свои пожелания/мотивацию (до 2000 символов)
и выбрать 1–50 предложений основного текста (по умолчанию 2), без приветствия и
завершения. Ответ GPT-4.1 mini в строгой JSON-схеме содержит ровно выбранное число
предложений и ID готовых фрагментов CV/JD/комментария. Опыт подтверждается только
CV; комментарий может подтверждать личную мотивацию, но не новый опыт.
Сервер сам подставляет точные цитаты и проверяет версии CV,
цитаты, цифры/латинские технологии, оговорки
учебного/планируемого опыта и длину (по умолчанию до 50 слов / 480 символов;
для N≤5 лимиты 20×N+10 слов и 210×N+60 символов,
для N>5 — 40×N+10 слов и 320×N+60 символов). Такая валидация
не заменяет смысловую проверку кандидатом. Письмо доступно для редактирования и
копирования; рассылка не выполняется.

COVER_LETTER_MODEL — серверная настройка, по умолчанию gpt-4.1-mini. Кэш в приватной
.cache/cover_letters (0600) учитывает ID/версию CV, ID/текст JD, модель, промпт,
комментарий и число предложений.
Повторный запрос кэшированного письма не вызывает OpenAI. UI не генерирует письма
при открытии рейтинга или изменении числа показанных вакансий.

Официальные ссылки: [Structured Outputs](https://developers.openai.com/api/docs/guides/structured-outputs),
[GPT-4.1 mini](https://developers.openai.com/api/docs/models/gpt-4.1-mini).

## Рекомендации HH для выбранного CV (0.5.4)

1. Выберите загруженное резюме HH и укажите «Карьерная цель для сравнения».
2. Нажмите «Открыть рекомендации HH для этого CV». Откроется `/search/vacancy?resume=<ID>`.
3. В этой вкладке нажмите значок расширения, задайте лимиты и нажмите
   «Собрать рекомендации HH с полными описаниями».
4. После сбора нажмите «Сравнить рекомендации HH с этим CV и целью».
   На странице рейтинга проверьте CV, цель и подборку, затем запустите анализ.

Сбор последовательно читает страницы и полные JD, сохраняет прогресс/ошибки и
поддерживает остановку. Стандартные ограничения: до 20 страниц / 200 новых полных
описаний за запуск / 4 минуты; повторный запуск переиспользует свежие JD.
У каждой вакансии `recommended_for` содержит ID резюме, для которых она найдена.
Метка добавляется и к ранее сохранённому полному JD без перезаписи его сниппетом.
Параметр `resume` защищён при пагинации, `from` считается служебным трекингом.

Подборка «Рекомендации HH для выбранного CV» включает только полные неархивные
вакансии с соответствующей меткой. Карьерная цель передаётся явно, старый расчёт
для другой подборки/цели не подставляется. Обычный поиск компаний остаётся отдельным
источником; рекомендации HH могут содержать любые компании и направления.
Этот режим доступен для HH-CV; файлы и Google Docs по-прежнему используются
для сравнения всех собранных вакансий. API вызывается только кнопкой анализа.

Живая проверка письма из экспортов: `.venv/bin/python scripts/verify_cover_letter.py
--resumes /path/resumes.json --vacancies /path/job-boards.json --vacancy-id hh_123`.
Команда вызывает локальный сервис и сохраняет результат в приватном
`.cache/live_checks/cover_letter.json`. Это платный запрос OpenAI: при ошибке
проверки разрешена одна попытка исправления, всего до двух запросов. Повторное
готовое письмо берётся из кэша. Команда не отправляет откликов.

Для писем добавлены пределы ожидания чтения хранилища и ответа сервиса:
при зависании кнопка снова доступна с понятным сообщением.

## 0.11.3: структура и диагностика

Фоновая точка входа содержит порядок загрузки модулей; навигация и работа с CV вынесены в `browser-navigation.js` и `resume-worker.js`. Компании описаны отдельными файлами `adapters/*.json`, общие правила — в `adapters/runtime.js`; `board-adapters.js` собирается командой `node scripts/build-adapters.mjs`. Команда `node scripts/check.mjs` проверяет сборку, синтаксис и все тесты исходного проекта.

В настройках подключения есть ссылка «Диагностика расширения и адаптеров». Она показывает фактические соединения, разрешения доменов и состояния задач; отчёт можно скопировать. Тексты CV, ответы, контакты и токены в отчёт не включаются. Проверка не запускает сбор или модель.

Карта модулей, цикл отладки и порядок добавления компании: [DEVELOPMENT.md](DEVELOPMENT.md). Новые JSON-описания не заменяют проверки ID, прав доступа, Python allowlist и адаптацию анкеты. Финальная отправка на корпоративных сайтах остаётся ручной. Проверено: 194 Node и 233 Python теста; страница диагностики 0.11.3 отвечает в установленном Chrome.

## 0.11.4: T-Bank, профиль IT + ML

Быстрый профиль в настройках поиска теперь задаёт «IT-разработка» и «Машинное обучение». Оба известных параметра выдачи (`direction=it-razrabotka`, `profession=ml`) устанавливаются до чтения; адаптер затем проверяет фактические флажки. Город сохраняется. Отсутствие фильтра ML останавливает сбор, а не превращает общую IT-выдачу в успешный результат. Сохранённый профиль используется ручным сбором и очередью. Пустой пользовательский профиль по-прежнему означает не менять фильтры.

## 0.11.5: профиль, город и цветные разборы

В веб-сервисе → Настройки добавлен редактор данных автозаполнения: город, соцсети / Telegram, портфолио и контакты. Данные версионируются в SQLite, не добавляются автоматически в запросы модели и предлагаются только в пустые поля. Смена данных отменяет прежние разрешения переноса.

Анкеты `career-fields-v2` поддерживают отдельный контрол города T-Bank. Предпросмотр для Москвы содержит «Россия, г Москва»; расширение должно нажать точный реальный вариант и проверить результат. Просто набранное слово «Москва» не подтверждает успех. Поле портфолио раскрывается до предпросмотра без ввода ссылки. Файлы, согласия и финальная отправка остаются ручными. Совместимость v1 сохранена. Выбор города протестирован на фикстурах, живой перенос в этом обновлении не подтверждён.

Разборы API и «Без API» имеют одинаковые цветные статусы с текстовыми метками. Цитаты вакансии и CV разделены визуально. Сообщение об утраченном контексте расширения подсказывает обновить страницу, предварительно сохранив тексты анкеты.

На сервере исправлена проверка цитат: точная цитата может пересекать границу фрагментов; добавленная моделью точка сверяется с исходным текстом, сохраняется оригинал; неправильный J-ID исправляется только при однозначном дословном совпадении, старый ID остаётся в диагностике. Семантическое сходство и выдуманные цитаты не принимаются. Сохранённые ответы повторно проверяются без оплаты нового запроса.
