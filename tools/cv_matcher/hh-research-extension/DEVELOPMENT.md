# Разработка расширения

## Быстрый цикл

В исходном проекте, из каталога `hh-research-extension` (dev-скрипты и тесты не входят в установочный ZIP):

```sh
node scripts/build-adapters.mjs
node scripts/check.mjs
```

Первая команда собирает описания компаний в `board-adapters.js`. Вторая проверяет актуальность сборки, синтаксис всех скриптов расширения и `../archive-web`, затем запускает тесты расширения (`*.test.mjs` в этой папке) и тесты веб-интерфейса (`../archive-web/tests/*.test.mjs`). npm и сторонние пакеты не нужны. После изменений перезагрузите установленное расширение в `chrome://extensions`. Уже внедрённый в страницы код обновится после повторного включения панели или перезагрузки страницы.

Ограниченное ожидание HH-скрипта — `wfReadWithin` из `hh-workflow.js`; новый код worker не создаёт собственный `Promise.race` с таймером. Адаптеры LinkedIn внедряются в вкладку один раз на загрузку страницы (`ensureAdapters`).

`board-adapters.js` — готовый файл для внедрения в страницу и загрузки service worker. Его не редактируют вручную: это один и тот же контракт для обоих окружений. Сборка проверяется тестом, чтобы изменения JSON не оставались незамеченными.

Общий принцип: `core` содержит правила и преобразования; `content` читает/меняет DOM; `worker` использует Chrome API, разрешения и локальный сервис. Очередью, версиями, согласованием и историей владеет Python. Код страницы не получает токен локального сервиса или API-ключ.

## Добавить или исправить адаптер

1. Для изменения вёрстки существующей компании исправьте её JSON. `hosts` — точные домены; `url` — HTTPS-адрес выдачи; `pages` — строка регулярного выражения для путей. `card`, `listingTitle`, `description`, `linkSelector` — CSS-селекторы. `layouts` переопределяет селекторы для конкретного объявленного хоста, как у Ozon.
2. Для новой компании добавьте отдельный JSON с уникальными `id` и `hosts`. Сборщик отклонит повторные хосты, неправильный домашний адрес, пустые селекторы и некорректный шаблон. Синтаксис CSS и соответствие реальной странице проверяются в браузере.
3. Добавьте точные optional host permissions в `manifest.json`; получение разрешения остаётся явным действием пользователя. Проверьте список источников в `discovery-worker.js`, `src/discovery.py`, настройки компаний и список провайдеров в `board-widget-core.js`. Новый JSON сам по себе не разрешает неизвестный сайт серверу.
4. Для собственного ID вакансии изменяйте `board-core.js` и `src/board_import.py` вместе. Стабильный ID обязан совпадать у обоих сборщиков; миграция существующих ID требует отдельного решения. Не принимайте выдачу за полную вакансию.
5. Начните с JSON-LD / собственного блока описания. Специальное извлечение секций размещайте в `board-content.js`. Не захватывайте анкету, похожие вакансии и текст нашего виджета. Неуверенное извлечение возвращает `needs_review`, блокировка — остановку, а не пустую успешную выдачу.
6. Добавьте фикстуры списка, полного описания, закрытой вакансии, изменённой вёрстки и пагинации с другим фильтром. Для анкеты отдельно проверяйте распознавание полей, изменение fingerprint и перенос только утверждённых значений. Чтение вакансии не означает поддержку отправки отклика.
7. Соберите bundle, выполните проверки и проверьте Chrome с разрешённым чтением сайта: список → полное описание → SQLite → панель → чтение анкеты. Проверяйте заполнение и отправку отдельно с требуемым разрешением пользователя.

Пользовательские селекторы в настройках подходят для пробного чтения нестандартной страницы. Они не создают автоматически полноценный адаптер анкет, расписания или отправки.

## Как найти причину сбоя

В настройках подключения откройте «Диагностика расширения и адаптеров». Отчёт показывает версию, ответы сервиса, отдельные соединения обработчиков, разрешения доменов, состояния задач и счётчики кэша. Его можно скопировать. Он не включает тексты документов, значения полей, URL вакансий, контакты или токены.

Если страница диагностики не отвечает, проверьте ошибки service worker в `chrome://extensions`. Фоновая точка входа теперь содержит только порядок загрузки модулей: ошибка указывает на конкретный модуль. Для ошибки извлечения используйте Console нужной страницы и тест соответствующего `content` / `core`.

Различайте: разрешение Chrome; наличие вкладки; вход на HH; свежий heartbeat обработчика; завершение конкретной задачи. Ни один из этих признаков не заменяет остальные. Диагностика только читает состояние и не создаёт вкладки, не забирает задачи из очереди и не вызывает модель.

## Сохранённые ограничения

Это постепенный рефакторинг: специфичные DOM-правила и Python-проверки ещё не превращены в независимые плагины. Бесконечная прокрутка, внешние iframe, файлы, согласия и нестандартные контролы требуют отдельных реализаций/ручного действия. Финальная отправка на сайтах компаний остаётся ручной. Проверки фикстур не заменяют живой проход каждого сайта.

### Контрол города T-Bank

`career-fields-v2` передаёт `control: tbank_city` только для поля города T-Bank. Python проверяет провайдера и версию, а предпросмотр фиксирует точную подпись варианта. `fillApproved` ищет связанную listbox и точный option; отсутствующий, неоднозначный или непринятый вариант останавливает перенос. Синхронный общий `fill` не может подменить выбор города обычным вводом. Проверяйте это отдельно от поддержки простых текстовых полей.
