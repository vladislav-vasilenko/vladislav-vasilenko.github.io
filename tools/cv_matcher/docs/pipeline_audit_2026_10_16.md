## Как получить письмо

1. В веб-сервисе выберите CV.
2. «Вакансии → Добавить одну вакансию · ссылка или текст».
3. Для чтения URL нужен только адрес. В настройках установленного расширения разрешите чтение сайтов компаний; Chrome опрашивает очередь раз в минуту.
4. Альтернатива: вставьте название, компанию и полный текст, подтвердите полноту и сохраните.
5. Откроется подготовка письма. Можно сгенерировать через API, обсудить с редактором или скопировать CV + вакансию + цель + пожелания + задание в ChatGPT без API.

Ранжирование и embeddings не являются обязательным шагом для письма. Вставленный вручную текст сам по себе не доказывает, что вакансия активна.

## T-Bank: профиль и анкета

Профиль фильтров сохраняется в «Сегодня → Поиск по расписанию». По уточнению владельца выбран только «IT-разработка»; «Аналитика и данные» исключена. Уровень и стаж не ограничены. Настройки применяются к T-Bank при ручном сборе и по расписанию. IT использует наблюдавшийся параметр `direction=it-razrabotka`, затем проверяется реальное состояние флажков; неизвестный или неприменившийся фильтр останавливает сбор.

Предпросмотр «Заполнить из профиля» успешно предложил фамилию с именем, почту, телефон и ссылку выбранного CV. Это **предпросмотр**, не подтверждённый живой перенос. Город с нестандартными подсказками, файл резюме, согласия и отправка остаются на сайте. Перенос требует отдельного разрешения на точные показанные значения. Проверки этого прохода не отправляли отклики или ответы рекрутерам.

## Проверки и практические границы

- 233 Python + 188 JavaScript тестов прошли; проверены синтаксис JS и компиляция Python.
- Платные модели в этих проверках не вызывались: генератор подставлялся в тестах. Работоспособность текущего ключа на реальном платном запросе не проверялась.
- /health: без кода 401, с кодом 200, версия протокола 10. Giga connected подтверждается свежим RPC, а не наличием настроек; длительный безотказный сеанс этим не доказан.
- Фоновая загрузка T-Bank в части проходов превышала прежние 25 секунд. Для компаний предусмотрены ожидание готового DOM до 60 секунд и сохранение вкладки для ручной проверки при таймауте. Это остаётся эксплуатационным ограничением; нельзя объявлять автоматическую фильтрацию надёжной на основании одних модульных тестов.
- Динамическая выдача/«Показать ещё» пока даёт partial. Отсутствие карточки не означает отказ или закрытие.
- Режим без API не создаёт новые embeddings. Если для нового текста нет вектора, он не попадёт в embedding-рейтинг до расчёта; об этом приходит явное сообщение.
- Лимит подборки — до 10 позиций за день, вечер дополняет остаток. Повтор неоткликнутой вакансии на следующий день ещё возможен.
- HH-отправка, завершённое интервью Giga и финальная отправка сайтов компаний не проверялись вживую в этом проходе. Факт чтения/заполнения не считается отправкой.

## Что ещё открыто

1. Один отдельно разрешённый контрольный HH-отклик с доказательством сайта → SQLite → Telegram.
2. Полная финальная отправка и подтверждение результата для каждого сайта компании: нестандартные поля, файлы, iframe, согласия.
3. Полный живой цикл Giga от утверждённого ответа до следующего вопроса и завершения интервью.
4. Постоянный инкрементальный inbox HH, единый подтверждённый контекст для всех генераторов, общая дедупликация HH/сайта компании.
5. Согласованность CRM/встреч/календаря и проверенный автозапуск после перезагрузки компьютера. Отдельный запуск процессов устраняет зависимость от текущего чата, но не заменяет системный автозапуск и наблюдение.

Прошлые аудиты сохранены в `audit-history`; их описания дефектов очереди, расписания и общего connected относятся к версии до 0.11.2.
