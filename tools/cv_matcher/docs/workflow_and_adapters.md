## Обновление 17.10.2026 — 0.10.10: ссылка на выбранное CV

Поле «Ссылка на резюме» / Resume URL / CV Link распознаётся отдельно. Для пустого обычного поля предлагается исходная HTTP(S)-ссылка именно CV текущего отклика. Она входит в точный предпросмотр и разрешение переноса; это не общий контактный параметр и не результат генерации. Собственный сохранённый ответ или значение на сайте имеют приоритет. Файловое CV без опубликованной ссылки не превращается в выдуманный URL.

На Avito кнопка «Заполнить из профиля» раскрывает режим «Ссылка», если выбранное CV имеет веб-ссылку, не приложен файл и однозначно распознана группа Файл / Ссылка. Само раскрытие не вводит URL; перенос данных выполняется после разрешения владельца. На других сайтах автоматически заполняется уже доступное обычное поле ссылки; переключатели/внешние iframe требуют отдельной реализации. Ссылка может требовать входа в HH или настройки доступа к Google Docs — доступность работодателю пока не проверяется.

Группа Avito `resume` и нативное поле «Ссылка на резюме» проверены в Chrome. Автоматическую передачу URL работодателю в этой проверке не запускали. Полный прогон: 213 Python и 164 Node теста прошли.

## Обновление 17.10.2026 — 0.10.9: профиль и перенос полей

В SQLite добавлен версионированный профиль для анкет: имя, фамилия, телефон, email, город. Его можно редактировать в веб-карточке и Telegram. Ручные ответы для конкретной анкеты имеют приоритет. Контакты не добавляются в профессиональный контекст модели автоматически.

На полной странице компании помощник показывает две задачи — «Соответствие» и «Письмо»; режим API / без API выбирается внутри задачи. «Заполнить из профиля» сначала показывает точный текст переноса. После отдельного разрешения владельца расширение переносит согласованные обычные поля в исходную открытую вкладку. Тексты, CV, вакансия и снимок анкеты привязаны к разрешению; изменённая форма останавливает перенос. Результат сохраняется в SQLite и отправляется в Telegram. При обрыве связи повторяется передача квитанции, а не ввод полей.

Кнопки переноса и перехода в веб-сервис разнесены с отступами; на узком экране занимают отдельные строки. Панель показывает подтверждённый результат либо остановку. «Обновить результат» только читает статус. Повторное включение виджета удаляет оставшиеся после перезагрузки расширения элементы, сохраняя форму работодателя.

Проверен живой сбор анкеты Avito LLM Core: 10 нативных полей → SQLite → карточка и уведомление Telegram. После разрешения владельца получена квитанция `fields_filled`; отклик остаётся неотправленным. Форматирование телефона допускается только при полном совпадении цифр. Контракт переноса протестирован для пяти адаптеров (Yandex, Sber, T-Bank, Avito, Ozon), но живое заполнение всех пяти сайтов не подтверждено.

Ограничения: файлы резюме, согласия, нестандартные списки и формы во внешнем iframe требуют ручного действия или отдельного адаптера. На Avito вопрос «Откуда вы узнали о вакансии?» остаётся ручным; на Yandex есть внешняя iframe-анкета. Финальная отправка на сайтах компаний пока выполняется пользователем. Независимый ежедневный сбор и пересчёт рейтингов всех job boards остаётся отдельным разрывом.

Проверка версии: 211 Python и 162 Node теста прошли. Новая вёрстка проверена в Chrome на Avito; тесты не означают живую проверку всех работодателей.

# Поиск, оценка и отклик

> Сверка 22.10.2026. История UX ниже сохраняет даты релизов. Текущие точки входа — [quickstart](applicant_quickstart.md); версия worker — в [README](README.md). [Hybrid/backfill](architecture/hybrid-collection.md) и [LinkedIn plan](integration/linkedin-adapters.md) используют общий архив, но разные capability.

Расширение 0.8.1 организовано в пять шагов: **Резюме → Поиск → Сбор → Оценка → Отклик**. Контекст выбранного CV остаётся видимым. Можно переходить между шагами; ничего не отправляется работодателям автоматически от перехода или просмотра.

1. Выберите актуальное CV и цель. Обновите HH/Google Docs после изменений.
2. Выберите HH или карьерный сайт компании. Фильтры HH относятся только к HH; на других сайтах настройте поиск на их странице.
3. На открытой выдаче запустите сбор списка и описаний. HH поддерживает пагинацию и рекомендации для того же CV. На корпоративных сайтах сбор идёт последовательно в текущей вкладке. Лимиты сохраняют частичный результат.
4. Откройте рейтинг и выберите **компанию**, модель и число вакансий. Фильтр применяется до отправки данных и до расчёта. Отправляется только выбранное CV. Готовые пары с теми же текстами, CV, целью и моделью читаются из SQLite; новые пары используют уже рассчитанные векторы. Если изменилось CV, векторы неизменившихся вакансий повторно не оплачиваются. Наличие вектора само по себе не доказывает наличие сравнения с новым CV.
5. Для подходящей вакансии подготовьте отклик и сопроводительный текст; проверьте ответы. Подробности очереди Telegram: [telegram_userbot.md](telegram_userbot.md).

## Два способа сбора, один архив

Chrome читает отображаемую страницу в сессии пользователя. Python/Playwright нужен для доступных ему карьерных сайтов. Это сменные способы получения данных; далее у них общий ID вакансии, формат, SQLite, версии и анализ. Автоматизация браузера не гарантирует доступ к сайту и не устраняет необходимость входа или ручного разрешения CAPTCHA.

| Адаптер | Страница | Извлечение |
| --- | --- | --- |
| Avito | https://career.avito.com/vacancies/?direction=data-science | Полный блок описания; существующий Python-парсер |
| Ozon.Tech / career.ozon.ru | https://ozon.tech/vacancies/ | Стабильные ID и блок описания; существующий Python-парсер |
| T-Bank | https://www.tbank.ru/career/vacancies/it/ | JobPosting / тематические секции, общий JS-адаптер для Chrome и Playwright |
| Yandex | https://yandex.ru/jobs/vacancies?professions=ml-developer | JobPosting / отдельный блок вакансии; Python-парсер |
| Sber | https://rabota.sber.ru/search/ | JobPosting / тематические секции; Python-парсер |

Незнакомый или неоднозначный текст сохраняется как **«Текст требует проверки»**. Он не попадает в платное сравнение до подтверждения полноты. На сайте архива можно сравнить текст с оригиналом и нажать **«Я проверил текст: описание полное»**. Название коллектора и версия адаптера сохраняются вместе с записью.

Пагинация следует только обнаруженным ссылкам той же выдачи с неизменными фильтрами. Для «Показать ещё» и бесконечной прокрутки пока загрузите следующую порцию на сайте и повторите сбор. Корпоративные сборы не объявляются доказательством полноты всего каталога и не подтверждают закрытие позиций.

Проверки включают фикстуры всех пяти адаптеров, совместимость ID Python/JS и актуальный публичный HTML Яндекса. Полный живой обход всех пяти сайтов не подтверждён: Ozon перенаправлял запросы, T-Bank не ответил в отведённое время, Sber отдал динамическую оболочку. Это не выдаётся за успешный сбор описаний.

## Отметки прямо на HH

Откройте выдачу или вакансию **https://hh.ru**, выберите CV в расширении и на шаге «Сбор» нажмите **«Показать отметки из БД на HH»**. Дополнительные постоянные разрешения на HH не нужны: используется текущий доступ activeTab.

Показываются «Сохранено в БД», сохранённая близость, покрытие требований Luna и до трёх красных меток «Не подтверждено: …» со счётчиком остальных. Оценки относятся к выбранному CV, цели, модели и сохранённому тексту вакансии. Непроверенное изменение оригинала HH обнаруживается только после нового сбора; при изменившемся названии оценки скрываются сразу. Отсутствие доказательства в CV не означает отсутствия навыка.

Переходы в этой вкладке в пределах HH сохраняют режим, пока действует разрешение Chrome. На новой вкладке включите его заново. Новые карточки обрабатываются при изменении страницы; данные читаются из локальной БД и обновляются раз в минуту либо кнопкой «Обновить из БД». Закройте режим кнопкой «Скрыть отметки». Никаких вызовов Luna/embedding API этот режим не делает; API-ключ и CV-текст не помещаются в страницу HH.


## Действия прямо в карточке и анкете HH · 0.8.1

Панель размещается отдельной строкой в карточке поиска и под заголовком полной вакансии. Метрики компактны, длинные неподтверждённые требования раскрываются списком целиком. «Разобрать» открывает панель и сначала проверяет SQLite; готовый разбор читается без API. Новый разбор создаётся отдельной кнопкой Luna. «Сопроводительное письмо» открывает комментарий/мотивацию и длину 1–50 предложений, затем формирует редактируемый черновик существующим генератором.

При выделении вопроса в карточке, полной вакансии или анкете с известным vacancyId появляется **«Генерация ответа на выделенный вопрос»**. Вопрос можно исправить, выбрать Luna / Terra / Sol и нажать «Предложить ответ». Чтение выделения и смена настроек ничего не генерируют. Ответ можно править и копировать; панель не отправляет анкету. Если в форме удалось распознать другое выбранное HH-резюме, генерация блокируется. При нераспознанном выборе проверьте соответствие CV вручную.

Для этих действий нужны синхронизированные полные CV/JD. Кнопки остаются видимыми, но недоступны при отсутствии полного описания, несовпадении CV с SQLite или явно изменившемся названии вакансии. Резюме выбирается в расширении; другое CV внутри HH не меняет этот контекст скрытно. Повторите включение панели после смены CV. Escape закрывает черновик.

После обновления перезагрузите расширение и локальный сервис. Chrome при перезагрузке расширения очищает код подключения из session storage: при необходимости снова подключите сервис через «Архив». Затем на нужной HH-вкладке включите отметки на шаге «Сбор».


## Пропуск закрытых вакансий · 0.8.2

На шаге «Сбор» по умолчанию включено **«Пропускать подтверждённо закрытые вакансии»**. Сборщики HH и корпоративных сайтов сверяются с сохранённым статусом перед очередью полных описаний. Закрытые записи не расходуют лимит описаний и не считаются переиспользованными свежими текстами. Отдельный счётчик показывает число пропущенных закрытых записей. В HH также прекращаются повторные проверки уже закрытых вакансий, отсутствующих в полном поиске.

Новые вакансии с неизвестной активностью продолжают проверяться. При видимом сообщении HH об архиве полный текст не извлекается; статус закрытия сохраняется, прежний полный текст и история остаются. Скрытая заготовка архивного сообщения не считается подтверждением закрытия. Отсутствие в выдаче и ошибки доступа не равны закрытию.

Если нужно проверить повторное открытие позиции, снимите флажок на этот запуск. В HH при такой перепроверке даже свежий сохранённый текст закрытой вакансии не мешает открыть её страницу и проверить актуальный статус. Для новых файлов достаточно перезагрузить расширение; перезапуск Python-сервиса не требуется.
