## Результат Transformer-проверки

Веса `ai-forever/sbert_large_nlu_ru` загружены из существующего локального кэша.
BGE-M3 в кэше оказался недокачан. Ollama не был запущен. Платные API не вызывались.
Обработаны 56 фрагментов, 15 вакансий. Использованы нормализованные embeddings,
сходство CV и отдельно карьерной цели; итог 55% CV + 45% цель.

Проверка выявила неудовлетворительный порядок: Ozon CV/OCR оказался №1,
pricing №2, Avito LLM Core №5; ML-платформа и generative recommendations
Avito оказались №12 и №13. Косинусное сходство не проверяет обязательный
опыт и различие между навыком, лабораторным проектом и промышленным обучением.

Для шести вручную отмеченных ролей с интересными задачами обучения моделей
(LLM Core, Item2param, generative recsys, DL search, Goods, Ozon internal products)
Recall@10 этой модели/конфигурации равен 4/6 = 66.7%. Это предварительная
разметка для персональной цели, а не общий benchmark качества SBERT.

Сохранённый экспертный рейтинг отделён от результата скрипта: он составлен
Codex по требованиям и фактам актуального CV. Новые поля LLM-промпта — готовность,
`career_goal_alignment`, `application_recommendation` — ещё требуют модельной
проверки на той же выборке. Не выдавать этот пилот за успешно запущенный ATS-сервис.

## Сравнение embeddings

OpenAI подключается существующим backend `EMBEDDINGS_PROVIDER=openai` и
`OPENAI_EMBEDDING_MODEL=text-embedding-3-large` либо `text-embedding-3-small`.
Для каждого embedder нужна отдельная база. Импортированный набор автоматически
разделяется по модели, провайдеру и версии embeddings.

На том же наборе следует сравнить small, large и локальный baseline:

1. Зафиксировать CV, полные JD, карьерную цель и экспертную разметку.
2. Сравнить Recall@10 и пары LLM Core > pricing, ML training > DS management.
3. Проверить, не пропали релевантные вакансии до LLM rerank.
4. Сравнить оценки требований с доказательствами: SFT подтверждено; multi-node
   pre-training, RL post-training и production DiT пока не подтверждены.
5. Выбирать модель по качеству на личной выборке, цене и времени обработки.

По официальной документации OpenAI large наиболее способна для английских
и других языков. Standard embeddings: small $0.02, large $0.13 за 1M input
tokens. Например, 1 000 JD по 2 000 токенов — $0.04 / $0.26 соответственно,
без учёта LLM оценки и инфраструктуры. Это расчёт при указанном объёме,
фактические токены надо измерить. Новые версии CV/JD пересчитываются, неизменные
фрагменты используют локальный кэш.

Источники: [large](https://developers.openai.com/api/docs/models/text-embedding-3-large),
[embeddings](https://developers.openai.com/api/docs/guides/embeddings),
[pricing](https://developers.openai.com/api/docs/pricing).

## Проверки кода

Проверены свежесть основного CV, запрет замены резервным при отсутствии основного,
хэш изменений, кэш векторов, сохранение длинного опыта, разные employer ID,
Ozon cross-domain/UUID/query-ID, исключение snippets/needs_review, чистота JD
и сохранение полного текста вместо более поздней краткой карточки.

Установка/перезагрузка расширения и реальные страницы HH остаются отдельным
сквозным тестом. Для неизвестного сайта JobPosting и CSS-рецепт требуют сверки
preview с оригиналом. Если описание внутри iframe/shadow DOM, нужен адаптер
либо открытие непосредственного источника. Загруженность выдачи и пагинацию
надо учитывать; ноль записей не является доказательством отсутствия вакансий.
