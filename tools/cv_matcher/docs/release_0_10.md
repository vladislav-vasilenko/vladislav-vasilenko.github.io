# Рабочий поиск 0.10.2 · 16 октября 2026

## Как обновить

В `chrome://extensions` обновите ML Research Vacancy Search, затем обновите уже открытые страницы HH. Новые обработчики фонового процесса загружаются при перезапуске расширения. Исходная папка — `tools/cv_matcher/hh-research-extension`. Копия и ZIP находятся в Documents/AI Vacancies Replies.

## Подключение

Страница параметров — мастер: Сервис → HH в Chrome → Готово. Подробно отображается один шаг. Завершённый шаг можно открыть повторно. Проверяются реальные возможности сервиса (`workflow`), а не условный номер версии. Код, принятый сервисом с поддержкой откликов, открывает следующий шаг. Проверка ограничена по времени; ошибка заменяет «Проверяю», а не остаётся внизу под зависшим заголовком.

Расширение открывает отдельную HH-вкладку после вашего разрешения. Состояние различает готовность, закрытую вкладку, отозванное разрешение, вход, CAPTCHA и неподтверждённый вход. Доступ к HH предоставляется пользователем. Код подключения хранится между перезапусками только при явной галочке. API-ключ не передаётся расширению.

В popup на шаге «Отклик» используется та же проверка. При готовом подключении основное действие — «Открыть мои отклики», а настройки остаются второстепенной кнопкой.

## Письмо и ChatGPT без API

В карточке отклика: генерация, диалог с редактором, ручная редакция и история. Длина — 1–50 предложений, доступны пожелания и выбор модели. «Скопировать CV + вакансию + промпт» сразу задаёт генерацию письма. «Обсудить с ИИ без API» готовит редакторский диалог; галочка позволяет включить текущий текст письма.

Для разбора навыков кнопка «ChatGPT без API» экспортирует точные R/J-фрагменты и JSON Schema. Ответ вставляется обратно в форму. Проверяются форма, категории, ID источников и точные цитаты вакансии. Проценты рассчитываются локально. Результат и исходные версии сохраняются в SQLite. Повторная вставка того же ответа идемпотентна. Изменение CV/JD не подменяет источники прежнего разбора.

На HH: «Разбор навыков без API», «Письмо без API». В распознанной форме отклика — письмо через выбранную модель и без API; контекст определяется выбранным в форме CV. Перенос письма в поле HH выполняется отдельной кнопкой, без отправки. Если CV не распознан однозначно или полного описания нет, действие блокируется.

## Исправления

- Изолированы составные события мыши/клавиатуры внутри Shadow DOM: кнопки помощника не должны запускать обработчик карточки HH и открывать вакансию в новой вкладке. Для кнопок отменяется также стандартное действие внешней ссылки.
- Ограничение в три R-ID теперь передаётся в строгую схему модели. Ошибки переполнения списка и неизвестного ID различаются. Некорректный оплаченный ответ сохраняется в SQLite для диагностики; повторное чтение не вызывает модель автоматически.
- Пустой результат чтения формы HH обрабатывается до обращения к `.state`. Старые технические ошибки переводятся в понятное сообщение Telegram. Если HH уже подтверждает отклик/приглашение, подготовка нового отклика прекращается после сохранения наблюдения.

## Очередь и будущий хостинг

Очередь — устойчивый источник задач и результатов; опрос раз в минуту — текущий транспорт. Для интерактивной работы можно добавить WebSocket-уведомление «появились задачи» с повторным подключением и резервным опросом. Уведомление не заменяет сохранение задачи, выдачу одному исполнителю и подтверждение результата.

При переносе сервиса на хостинг расширение должно само устанавливать исходящее HTTPS/WSS-соединение. `127.0.0.1` облачного сервера не является компьютером пользователя. Локальные API-ключ и сессия Telethon требуют отдельного локального исполнителя, если их нужно сохранить на компьютере. Для нескольких пользователей нужны отдельные устройства, авторизация, привязка задач к пользователю, отзыв подключения и проверка каждого разрешения. Для текущего личного сервиса достаточно SQLite; отдельный брокер очередей не требуется.

При неизвестном результате отправки нельзя автоматически повторять её: сначала сверяется HH. Надёжность очереди не означает гарантию единственного внешнего эффекта в чужом интерфейсе.

Первичные источники: [жизненный цикл Chrome MV3](https://developer.chrome.com/docs/extensions/develop/concepts/service-workers/lifecycle), [WebSocket в расширениях](https://developer.chrome.com/docs/extensions/how-to/web-platform/websockets), [сообщения и проверка отправителей](https://developer.chrome.com/docs/extensions/develop/concepts/messaging).
