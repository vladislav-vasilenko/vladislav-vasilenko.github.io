# Career Skills Intelligence: аудит и границы реализации

20.10.2026. Phase: Career Skills Intelligence & Learning Prioritization.

## Что уже существует

- [skill_analysis.py](../../src/skill_analysis.py): точные J/R-цитаты, `must/nice/unclear`, `confirmed/partial/studying/not_evidenced/explicit_gap`. Кэш `skill_analyses` привязан к CV/JD/цели/model; [skill_history.py](../../src/skill_history.py) сохраняет происхождение. Есть платный и внешний offline импорт.
- [candidate_profile.py](../../src/candidate_profile.py): детерминированные контакты и portfolio URL. Это не профиль доказанных профессиональных навыков.
- [candidate_facts.py](../../src/candidate_facts.py): версионированные уточнения владельца; [resume_supplements.py](../../src/resume_supplements.py): блоки опыта отдельно от HH CV.
- [career_analytics.py](../../src/career_analytics.py) и [luna_batch.py](../../src/luna_batch.py): общий текущий рейтинг, фильтры карты, top-50, предварительный просмотр платных расходов и offline export/import.
- [CareerApplication](../../src/career_application.py), [career_orchestrator.py](../../src/career_orchestrator.py): общий слой для Web/Telegram/MCP; Telegram не получает отдельный engine.
- SQLite `archive_meta` уже хранит версионируемые локальные настройки, а `candidate_facts` — историю уточнений. Новая БД, сервис и vector pipeline не нужны.

## Последовательность

1. Локальный словарь нормализованных навыков и версионированные many-to-many треки, с прозрачными prerequisites и ориентировочными затратами.
2. Отбор только top-K актуального персонального рейтинга среди полных незакрытых вакансий в фильтрах карты; при выборе потока — пересечение с его IDs. Без fallback на первые/самые свежие вакансии при отсутствии рейтинга.
3. Детерминированное извлечение `required/preferred/mentioned` с точными исходными цитатами; использование актуальных сохранённых Luna-источников. Упоминание не становится required. Confidence — эвристическая уверенность извлечения, не измерение знания кандидата.
4. Независимые evidence axes из CV, Facts, supplements, сохранённых разборов и явных уточнений пользователя. Неизвестность не равна отсутствию навыка. GitHub URL без описания результата не доказывает исследовательский уровень.
5. Объяснимый priority engine: weighted demand по уникальным вакансиям, track importance, подтверждения и стоимость ближайшего действия. `learn/practice/validate/document_in_cv/publish_project` различаются. Для unknown первым действием служит validate, для уже подтверждённого вне CV — document_in_cv.
6. Dashboard / heatmap / priority / impact / evidence и Telegram top-3, работающие над одной сохранённой выборкой. Изменение evidence создаёт новую версию локального плана; embedding/Luna scores не подделываются и не пересчитываются платно без согласования.
7. Размеченные fixtures, metrics извлечения и негативные сценарии. Маленький quality set не объявлять доказательством production accuracy.

## Хранение без новой инфраструктуры

Использовать существующий `archive_meta` с отдельными namespaces для immutable track versions, requirement snapshots, evidence revisions, plan snapshots и выбранного контекста. CV и raw Luna не менять. Ссылки на исходные версии и hashes включать в каждый план. Старые планы остаются историческими; изменения CV/JD/Facts/track/model/evidence меняют fingerprint и дают новый план. Записи пользователя отделены от автоматически извлечённых источников.

Ресурсы проверяются по первичным источникам при разработке, дата проверки сохраняется в каталоге. Рабочий расчёт не ходит в сеть, не скачивает репозитории, не вызывает LLM. Время обучения — редактируемая плановая эвристика, не обещание профессионального освоения за N часов.

## Границы

- Формула priority/impact не является вероятностью найма, процентом освоения или контрфактуальным приростом embeddings.
- Завершённая лекция/лабораторная не превращается в коммерческий опыт.
- Подтверждённые предпосылки, изучаемые и unknown prerequisites показывать раздельно; перед advanced task сначала проверять/осваивать нужные основы.
- Массовый платный Luna остаётся существующим owner-confirmed top-50 pipeline. Модуль skills использует кэш и локальные правила, API requests = 0.

## Реализовано и проверено (20.10.2026)

Рабочий вертикальный модуль, а не отдельный сервис:

- [Каталог](../../src/career_skills_catalog.py): 33 нормализованные компетенции, шесть стартовых many-to-many треков. В вебе можно менять состав, важность и диапазон часов упражнения, сохранять новую версию или создать трек с новым ID.
- [Извлечение](../../src/career_skill_requirements.py): исходные непрерывные цитаты с offsets, три типа требований, negation, section boundaries, confidence, provenance; локальные правила дополняются только актуальным Luna-кэшем. `bare metal`, NVIDIA MPS и Triton Inference Server не становятся Apple Metal / Triton kernels.
- [Evidence](../../src/career_skill_evidence.py): CV, Candidate Facts, resume supplements, owner annotations, валидные текущие Luna-источники. Упоминание, обучение, работа, проект, эксперимент, частичность и явный пробел различаются. Комбинированная Luna-цитата не подтверждает навык, которого нет в CV-цитате. План/курс нельзя сохранить как профессиональный опыт.
- [Priority engine](../../src/career_skills.py): топ-K (1–50) из полного актуального рейтинга, пересечение с фильтрами карты и выбранными IDs. Требования дедуплицируются по `(skill,vacancy)`. Формула и ограничения возвращаются клиентам. Unknown → validate; опыт вне CV → document_in_cv; завершённое обучение → practice; проект без описанного опубликованного результата → publish_project. Изучение рекомендуется при явном пробеле или текущем обучении, а не из-за отсутствия слов в CV.
- [Хранение](../../src/career_skills_store.py): immutable track/evidence/plan revisions, optimistic revision guard, история, контекст выборки в существующем `archive_meta`. Семантические embedding/Luna-оценки не подделываются. Feedback пересчитывает приоритеты и `vacancy_evidence` для выбранных актуальных вакансий; старые планы сохраняются.
- [Web](../../archive-web/career-skills.js): пять представлений, редактирование треков, запись/отзыв evidence и история. Навыки используют те же фильтры; нажатие потока/точки ограничивает когорту, перестроение — явной кнопкой. Требования и состояния подтверждений доступны в heatmap. Загрузка модуля изолирована от основной аналитики, есть retry при недоступном asset.
- [Application API](../../src/agent_routes.py): POST `/archive/agent` с `skills_catalog`, `skills_plan`, `skills_track`, `skills_evidence`, `skills_history`. Используется существующая авторизация. Обёртки находятся в [CareerApplication](../../src/career_application.py), [conversational router](../../src/career_orchestrator.py) и [Telegram](../../src/workflow_bot.py) вызывают их. Нового Telegram-agent нет.

### Как пользоваться

1. Открыть **Карта возможностей**, выбрать CV, фильтры или поток/точку графика.
2. Ниже карты — **Career Tracks · навыки и обучение**. Выбрать трек, топ-K, нажать **Построить план навыков**. Изменение фильтров помечает план как требующий перестроения.
3. Раскрыть навык: точные требования и вакансии, независимые подтверждения, действие и необходимые основы. Заблокированные advanced ресурсы показывают непроверенные prerequisites.
4. В **Добавить лабораторную, проект или подтверждение опыта** записать фактический результат и при наличии ссылку. Сохранение создаёт ревизию и новый план, не меняет исходный CV. Можно отозвать уточнение без удаления истории.
5. В Telegram — **Навыки и обучение** либо «Какие три навыка мне важнее всего изучить для перехода в Generative Models Research?». Используется основной CV и его последняя сохранённая в модуле выборка; названный трек может её переопределить. Без сохранённой выборки — топ-50 актуального рейтинга, без достаточных данных — понятная ошибка, без запуска платного API или нового поиска.

### Ресурсы

Официальные материалы MIT 6.S184 (2026), Stanford CS336, PyTorch/FSDP2/torchao/MPS, Python, NVIDIA CUDA, Apple MLX, Deep Learning, Modern Robotics, оригинальные Flow Matching/DDPM papers перечислены в каталоге с URL, prerequisites, topics и датой проверки 20.10.2026. Ссылки на MIT labs ведут на официальный курс с лабораторными. Для тем без проверенного подходящего ресурса (например ROS/SLAM в текущем каталоге) показывается отсутствие покрытия, а не случайная ссылка. Полный аудит ресурсов GitHub, автоматическое чтение кода и аттестация качества исследований не реализованы: URL считается непроверенным источником, профиль аккаунта не равен опубликованному проекту.

### Проверка и границы качества

- **369 Python / 320 JavaScript**: полный изолированный прогон и JS suite прошли. Включены 19 новых Python сценариев и два JS regression test, включая auth/revisions, идемпотентность естественного запроса, владельца Telegram, stale ranking, prerequisites, feedback, неизвестность и отказ загрузки asset.
- [Размеченный набор](../../src/tests/fixtures/skill_requirements_labeled.json): 28 development случаев, три фрагмента предоставленных вакансий и синтетические границы. [Оценка](../../src/skills_quality.py), запуск `.venv/bin/python scripts/evaluate-career-skills.py`: 35 TP, 0 FP, 0 FN, 37 точных цитат, 0 нарушений offsets. Precision/recall 1.0 **на этом малом регрессионном наборе**, не оценка качества на всём рынке. Нужен независимый размеченный held-out набор до расширения словаря/автодействий.
- Live: обновлены локальный backend и бот, в браузере открыт архив, построен и сохранён план для текущего CV на **50 реальных вакансиях**. Все пять блоков отрисовались, JS error log пуст. API requests = 0. Тестовые факты/лабораторные в рабочую базу не добавлялись; real Telegram send и платные Luna не запускались. Telegram проверен через настоящий update-handler с фиктивным transport.
- Извлечение ограничено словарём и консервативными правилами; нераспознанные фрагменты требований видны отдельно. CV/навыки не оценивают личность или вероятность найма. Автоматические признаки — доказательства в тексте, не независимая профессиональная аттестация.
- Исторический план не считается актуальным после смены CV/JD/Facts/треков/моделей/evidence. Новый расчёт строится на текущих версиях и исключает устаревший рейтинг; обновление embeddings или Luna остаётся отдельным согласованным действием.

## Уточнение основы плана и Career Path (20.10.2026)

Веб предлагает три независимые основы:

1. **Выбранные вакансии**: поиск по названию/компании, флажки, выбор лучших десяти, максимум 50. Список ограничен текущими фильтрами, полным описанием и актуальным рейтингом. В расчёт попадают только отмеченные IDs; пустой выбор не подменяется всем архивом.
2. **Выбранные направления**: категории берутся непосредственно из `career_analytics.TAXONOMY`, совпадение хотя бы по одному тегу (не только primary category). Навыки строятся из фактических `required/preferred` выбранных вакансий, без ограничения шестью шаблонами. Остальные фильтры карты сохраняются. Нераспознанные навыки по-прежнему требуют расширения словаря, а не выдаются за отсутствие спроса.
3. **Карьерные треки**: шесть стартовых редактируемых шаблонов — целевые профили компетенций. `career_path` строит последовательность от текущего CV/evidence к целевому профилю: основы/prerequisites → целевая практика → описание и публикация результатов. Unknown предпосылки сначала проверяются. Это путь подтверждения навыков, а не автоматический граф должностей и не обещание трудоустройства.

Backend `mode=vacancies|directions|track`, `direction_ids`, `vacancy_ids` сохраняются с выборкой CV и доступны общему application layer/Telegram. Для derived plans важность словаря одинакова; различаются спрос, required/preferred, уверенность, позиция в рейтинге, свидетельства и трудоёмкость. При явном запросе нового карьерного трека Telegram переключает `mode=track`. Engine revision `skills-priority-2` отделяет новые планы от исторических.

В Web дополнительно виден точный состав **В расчёте: N вакансий**, ссылки, источник и история. На границе 50 выбранных вакансий UI/API не создают скрытый более широкий cohort. Старые плановые snapshots сохраняются.

Проверки расширены: **373 Python / 323 JS**. Live проверены ручной checkbox (счётчик 1 из текущего рейтинга), соответствующие категории воронки, восстановление режима трека и успешный Career Path по 50 вакансиям; API requests=0. Изменения основных четырёх экранов описаны в [workspace UX](../integration/workspace-ux.md).
