# Корневой проект, расширения и корпоративное заполнение

> Сверка 22.10.2026. Текущая версия основного executor — в [README](../README.md). Наблюдения про установленные 0.11.18–0.11.20 ниже исторические. Для LinkedIn развивать capability adapters основного расширения; [контракт](../integration/linkedin-adapters.md). Legacy Workday не объединять механическим копированием manifests.

Аудит: 20.10.2026; актуализация границ: 22.10.2026. Это карта фактических границ, а не заявление о полном live E2E всех сайтов.

## Почему код выглядит дублирующимся

| Каталог от корня репозитория | Назначение | Решение |
|---|---|---|
| `src/` | TypeScript-интерфейс публичного CV/портфолио, экспорт и старые инструменты анализа | Сохранить как отдельный клиент; не смешивать с Python backend |
| `content/` | Редактируемые CV JSON/Markdown, языки и варианты описания опыта | Сохранить как источник документов, а не вторую базу подтверждённых Candidate Facts |
| `public/` | Публичные документы и статические ресурсы | Не импортировать всё автоматически в персональное evidence |
| `dist/` | Производная сборка Vite | Не редактировать вручную и не использовать как основной исходник |
| `cv-api/` | Отдельные облачные endpoints публичного проекта; старые анализ/письмо/генерация | Не использовать скрыто из локального workflow; переносить потребителей постепенно |
| `autofill-extension/` | Legacy Workday: опыт/образование, публичное CV, старый `/api/generate` | Сохранить Workday; ограничить внедрение этим семейством сайтов |
| `tools/cv_matcher/src/` | Python: SQLite, CV/JD, evidence, письма, формы, approvals, CRM | Общий application layer для персональных сценариев |
| `tools/cv_matcher/archive-web/` | Локальный Web-клиент общего слоя | Не хранить собственную бизнес-логику отправки или отдельный профиль |
| `tools/cv_matcher/hh-research-extension/` | Исполнитель Chrome: сбор, формы, квитанции | Единственный поддерживаемый исполнитель локальных корпоративных форм |

Старое расширение не подключено к локальной очереди. Его публичное CV не совпадает автоматически с выбранным immutable snapshot в сервисе. Объединять manifests или копировать popup целиком нельзя: различаются данные, жизненный цикл, approvals и endpoints. В проверенном профиле Chrome было установлено основное расширение 0.11.18; legacy Workday не обнаружено в списке установленных расширений.

## Найденные причины сбоев

1. В локальной очереди была необработанная `career_open`, а последний heartbeat `career` отставал примерно на три дня при свежих HH/collection/resume. `careerWorkflowPulse` прекращал работу при **любой** занятой вкладке; одновременные минутные alarms создавали возможность голодания обработчика. Теперь сериализация ограничена собственным worker и конкретной вкладкой.
2. Chrome использовал 0.11.18 при исходниках 0.11.19. Изменения файлов не обновляют уже зарегистрированный service worker автоматически. Исправленная версия — 0.11.20; после обновления нужна проверка heartbeat.
3. В журнале Chrome были `Resource::kQuotaBytes quota exceeded`. Это подтверждает ошибки хранения, но не устанавливает текущий объём каждого ключа. Нельзя исправлять их слепой очисткой CV/кэша. Для чтения корпоративной формы большой JD теперь сразу сохраняется в SQLite; квитанция заполнения доставляется даже при переполненном optional local cache с fallback journal в session storage. Если оба journal недоступны и сеть оборвалась, исход требует сверки; автоматического повтора заполнения нет.
4. Сайт и виджет использовали два разных пути чтения. Только один обновлял проверку активности JD. Теперь оба используют `careerCaptureForm`: свежая полная вакансия → SQLite → снимок анкеты → привязка вкладки. Архивная, другая или неполная вакансия не становится активной из-за наличия формы.
5. `careerOpenForm` фактически не повторял чтение при позднем появлении формы: `careerInspect` сразу бросал исключение. Теперь есть ограниченный retry только для ещё не открытой/не смонтированной формы. Вход, неоднозначность и iframe не маскируются retry.
6. После письма UI мог снова предлагать письмо вместо формы; состояние HH выдавалось за общее соединение. Следующий шаг и связь корпоративного worker теперь определяются отдельно.

## Границы по сайтам

Для Yandex, Sber, Ozon и Avito предусмотрен общий перенос согласованных **нативных** полей на распознанной странице конкретной вакансии. Fixture-тесты пяти провайдеров, включая T-Bank, не доказывают live-совместимость каждой текущей анкеты.

Внешние iframe, отдельные ATS-страницы без проверенной связи с vacancy ID, загрузка файлов, согласия и произвольные custom widgets остаются отдельными capabilities. У Яндекса публичная страница проверенной вакансии показывает «Войти и откликнуться»; необходимость входа распознаётся отдельно. Встроенная форма получает явный диагноз `embedded_form`, а не обещание, что ещё одно разрешение её заполнит.

Не расширяли доменные разрешения и не реализовывали универсальное cross-origin заполнение. Следующий этап для iframe: определить реальный frame URL в авторизованной сессии, зафиксировать связь parent job → frame/document, ограничить источники, включить URL/frame/fingerprint в согласование и квитанцию, проверить смену frame до первого ввода. До этого нельзя выдавать произвольный iframe за форму выбранного работодателя.

## Рефакторинг Web workflow

- [workflow.js](../../archive-web/workflow.js): вход, навигация, список, общий контекст и HH-сценарий; исходная сжатая запись развернута.
- [workflow-core.js](../../archive-web/workflow-core.js): чистый выбор следующего шага, безопасное чтение результата, диагностика связи.
- [workflow-letter.js](../../archive-web/workflow-letter.js): письмо, редактор, версии и offline prompt; свежесть контекста проверяется перед продолжением асинхронной операции.
- [workflow-career.js](../../archive-web/workflow-career.js): открытие формы, профиль, вопросы, preview/approval и результат отдельными функциями.

Формат JS сохранён, новый bundler не добавлен. Это первый ограниченный этап: HH, CRM и список можно выделять дальше по измеримым проблемам. Переход на TS сам по себе не исправляет DOM, очередь или работу источников. Начинать проверку типов целесообразно с request/result contracts и чистых модулей, сохраняя текущий протокол.

## Как продолжать объединение

1. Персональное действие проходит через CareerApplication/существующий workflow; Web, Telegram, MCP и Chrome не создают параллельные case/profile/approvals.
2. Документы `content/` при необходимости импортируются как проверяемые версии резюме с provenance. Редактирование публичного Markdown не повышает профессиональную подтверждённость автоматически.
3. Workday переносить отдельно как capability к общему snapshot → preview → approval → verified fill, затем выводить legacy endpoint из использования. Сейчас Workday сохранён, а не выдан за готовый новый адаптер.
4. Общие старые генераторы в `cv-api` удалять лишь после карты потребителей, переноса интерфейсов и проверки совместимости. Публичное портфолио не зависит от доступности localhost у читателя.
5. Хранение больших описаний и истории — SQLite; browser storage использовать для нужного исполнителю состояния и ограниченного кэша. Политику компактации добавить с подтверждением сохранения в архиве и восстановления, без удаления несинхронизированных данных.

## Автопроверки и ограничения проверки

Новые [UI-сценарии](../../archive-web/tests/workflow-ui.test.mjs): канал/состояние → следующий шаг, отсутствие побочных действий при render, preview и явное разрешение, stale activity, смена карточки, порядок save→chat и загрузка зависимостей.

Новые [worker-сценарии](../../hh-research-extension/career-worker.test.mjs): занятая посторонняя вкладка, поздняя форма, вход, busy original tab, архивный JD, отказ sync, переполненный кэш и повтор доставки receipt без повторного ввода. [Form-тесты](../../hh-research-extension/career-form.test.mjs) различают вход, iframe и отсутствие формы.

Backend: [readiness и assets](../../src/tests/test_application_readiness.py), существующие [single-use transfer проверки](../../src/tests/test_career_field_transfer.py). Полный Python suite запускать через `scripts/test-isolated.py`; JS — через `hh-research-extension/scripts/check.mjs`. Реальных откликов и платных запросов в этих проверках нет. Offline-тесты не подтверждают финальную отправку на карьерных сайтах.
