# Сравнение нескольких резюме под карьерный трек

Реализовано 22.10.2026. Вход: Резюме → «Сравнить резюме» → выбрать 2–7 снимков → «ИИ-разбор выбранных резюме · трек и хронология».

## Три разных способа сравнения

1. Диаграмма / diff: локальные совпадения текста и интервалов, без LLM.
2. API: Luna или Terra, явный просмотр контекста и подтверждение одного платного запроса.
3. Без API: подробный промпт с теми же источниками и схемой ответа. JSON можно вернуть; сервер проверяет источники и точные цитаты перед сохранением.

## Источники и результат

Используется существующий версионируемый каталог Career Skills tracks. Выбор трека задаёт цель конкретного разбора и приоритеты компетенций. Это не скрытое изменение всех фильтров вакансий или основного CV.

Контекст фиксирует ID каждого CV, номер снимка, content hash, название, версии дополнений / Candidate Facts и revision трека. Можно выбрать разные версии одного CV. Дополнения явно отделяются от снимка.

Выписку из трудовой книжки пользователь вставляет или извлекает из TXT, MD, DOC, DOCX, PDF, Pages существующим локальным импортом; XLS/XLSX читаются локально через [python-calamine](https://github.com/dimastbk/python-calamine) без исполнения формул. Перед включением нужна проверка текста. Контакты и типичные поля личных реквизитов маскируются, но это не гарантия полного автоматического обезличивания: интерфейс требует оставить только профессиональные события. Сканы без текстового слоя требуют OCR вне текущего модуля. Выписка не сохраняется как отдельное резюме и не изменяет Candidate Facts автоматически. Контекст и проверенный отчёт хранятся локально в SQLite.

Разбор рекомендует основу резюме под трек, ранжирует все выбранные снимки, сопоставляет хронологию, выделяет расхождения / неопределённость и предлагает конкретные редакторские правки. Каждое утверждение сопровождается source_id и цитатой. Противоречие требует минимум двух разных источников; исходная цитата правки должна принадлежать указанному CV. Это проверка ссылок, а не доказательство истинности рассуждений модели.

Трудовая книжка подтверждает только представленные трудовые события. Она не доказывает стек / достижения и не обязана содержать фриланс, исследования и проекты. Отсутствие сведений не равно отсутствию навыка. Параллельные периоды нельзя суммировать. При неполных датах или различии бренда и юрлица модель должна спрашивать уточнение.

## Повторное использование архитектуры

`resume_portfolio.py` готовит контекст и валидирует результат. `resume_review.py` использует прежние таблицы `resume_review_contexts`, `resume_review_attempts`, `resume_reviews`, кеш и журнал одного платного запроса. Новая БД и отдельный платный pipeline не создаются.

API: `/archive/resume-review`, операции `prepare_portfolio`, `prompt`, `generate`, `import`. Авторизация и проверка Origin прежние. Сервер требует `confirmed=true` для нового платного portfolio-разбора. Для подготовки / экспорта / импорта API модели не вызывается. Точные цены не вычисляются: интерфейс показывает символы, грубый диапазон входных токенов и выбранную модель. Объём контекста ограничен 300 000 символов.

Контекст меняется при смене снимков, трека, модели, вопроса, дополнений или выписки. SDK-повторы отключены. Неопределённый платный запрос автоматически не повторяется. Повторный просмотр кеша бесплатный. Резюме и статусы откликов не переписываются.

Вопрос для обсуждения включается в контекст: можно запросить уточнение рекомендаций, подготовив новый запрос. Это пока структурированный разбор, а не отдельный многоходовый чат с памятью всей переписки. Для свободного обсуждения предусмотрено копирование полного контекста в свой LLM-чат.

## Проверка

Автотесты охватывают семь снимков, точные цитаты, чужие снимки, дубли, подтверждение выписки, маскирование реквизитов, отказ неподтверждённому платному запросу, кеш, запрет повторной оплаты после таймаута, версии трека/фактов, оба UI-маршрута. Реальные платные вызовы при разработке не выполнялись.


Дополнительно допускается до 10 именованных источников: выписки, договоры/справки, фрагменты CV, другие документы или собственные заметки. Каждый текст редактируется и подтверждается независимо. Несколько файлов читаются последовательно; документ остаётся отдельным источником, а не автоматически новым CV. Для каждого хранится текстовый hash и provenance label/type в контексте. Импорт Excel сохраняет названия листов, номера строк и типизированные даты ISO; числа без формата даты не превращаются в даты произвольно. Лимиты: файл 12 МБ, 20 листов, 5000 строк / 100 столбцов на лист, 60 000 символов на источник, 300 000 на весь контекст. Части документов с потерянной разметкой требуют ручной проверки.

UX: основной путь — выбрать снимки → трек → подготовить контекст → API или копирование. Подтверждающие документы, полный промпт и импорт JSON свёрнуты. Сначала показаны рекомендуемая основа и первые пять правок; сравнение всех CV, хронология и полный список приоритетов раскрываются отдельно. Шапка CV разделяет «Режим чтения» и меню «Экспорт».

Финальная изолированная проверка: 431 Python-тест прошёл, включая реальный минимальный XLSX и типизированные даты XLS через подмену reader. Платные модели не вызывались. Editor карьерного пути как самостоятельный раздел — дальнейшее развитие; текущий модуль использует существующий каталог целевых профилей.
