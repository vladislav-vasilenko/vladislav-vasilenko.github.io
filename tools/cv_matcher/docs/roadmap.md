# План развития

Пересмотрено 23.10.2026. Это план по текущему коду и последним требованиям пользователя; старые ТЗ сохраняются в [ideas](ideas/README.md). Наличие пункта в плане не означает выполненную интеграцию.

## Реализованная основа

- Общий локальный архив SQLite: версии CV/JD, evidence, рейтинг, анализы и CRM.
- Общий application layer, scheduler, задачи Web/Telegram/MCP, разрешения и receipts.
- Гибрид Python/Chrome, отдельная возобновляемая дозагрузка JD, прогресс и причины ошибок.
- Документное сравнение CV с потоками чанков; промпт без API и портфельный разбор Luna/Terra с дополнительными документами.
- Редактируемые карьерные траектории с критериями/подтверждениями, подбором CV и связями вакансий.
- GitHub Runs: история, управление поддержанным сборщиком и проверяемый импорт результатов в SQLite.
- HH → публичный Title/опыт, локальное введение RU/EN, выбранные исследования/визуализации; статические EN/RU страницы, восемь оформлений и публичный PWA.

Границы каждого пункта: [текущее состояние](architecture/current-state.md). Живой E2E всех внешних сайтов не заявлен.

## LinkedIn: реализация и оставшаяся приёмка

Текущая реализация, живая проверка и ограничения: [LinkedIn — профиль и вакансии](integration/linkedin-adapters.md).

| Шаг | Результат | Приёмка |
|---|---|---|
| 1. Возможности и чтение | Adapter активной сессии: собственный профиль и доступная рекомендованная выдача | RU/EN fixtures, login/partial/drift, без записи и отправки |
| 2. Карточки и очередь JD | Устойчивые ID, короткие описания, пакетные полные тексты, Apply metadata | Дубли, виртуализированный список, остановка/продолжение, частичные ошибки, защита свежего полного текста |
| 3. Сверка профиля | Title, About, опыт, образование, сертификаты против HH/локального профиля | Трёхсторонний diff, provenance, неоднозначные совпадения и переводы видны |
| 4. Управляемая запись | Предпросмотр выбранных полей, проверка актуальной базы, заполнение и read-back | Устаревшая форма/профиль блокируют запись; uncertain не повторяется слепо |
| 5. Публичная проекция | Согласованный набор полей, включая образование/сертификаты | Сайт получает только разрешённые данные, без циклических перезаписей |

Раздел и адаптеры активной Chrome-сессии реализованы; прочитаны доступные карточки и четыре секции собственного профиля. Полнота About/заголовка и все варианты редакторов проверяются отдельно. Живое сохранение профиля и действия с контактами не выполнялись. Apply/Easy Apply metadata и переход не равны отправке отклика.

## Дальнейшие направления

1. Привязать свежий поиск и расписание к выбранному этапу траектории, с явным просмотром изменений scope. Сейчас выбор пути не меняет глобальное расписание.
2. Проверять качество приоритетов на размеченных примерах: Precision@20/NDCG, качество required/preferred, ложные skill gaps; не выдавать cosine за вероятность интервью.
3. Закрывать корпоративный сценарий по одному сайту: чтение → форма → заполнение → проверка. Универсального submit нет; поддержка фиксируется по capability.
4. Укрепить provenance от рекомендации до CRM, общие лимиты paid attempts и согласование Giga; сохранить existing queues и SQLite.
5. Восстановление адаптеров через Luna — отдельный эксперимент с декларативными правилами, dry-run, ограничениями и версионированием, [спецификация](ideas/llm-adapter-repair.md). Код модели не исполняется.
6. Решение о 24/7 принимать отдельно: sleep/recovery не делает ноутбук always-on. GitHub Actions решает публичный сбор, но не доступ к авторизованной Chrome-сессии.

## Условия завершения этапа

Код и документация с проверяемыми ссылками → изолированные unit/contract tests → живое чтение разрешённой страницы → подтверждённая проверка записи, если она входит в этап. Фиксировать версию adapter/protocol, ограничения и наблюдаемый результат. Не использовать настоящие отклики или платные модели как скрытый smoke-test.
