# Эволюционная AI-native архитектура и стоимость

> Сверка 22.10.2026. Application layer/MCP, GitHub import и публичная проекция уже реализованы. [Актуальная архитектура](../architecture/current-state.md) заменяет предположения исходного ТЗ об их отсутствии.

Статус: принципы будущих итераций. Источники: [большое ТЗ](sources/evolutionary-career-platform.md), [AI-native](sources/ai-native-extraction.md).

## Переиспользовать существующее

Три продуктовых сценария — Radar, Browser Copilot, Application Agent — не требуют трёх новых сервисов. Уже существуют [CareerApplication](../../src/career_application.py), [bounded orchestrator](../../src/career_orchestrator.py), [runtime](../../src/career_runtime.py), [task controls](../../src/agent_tasks.py), [MCP](../../career_mcp.py), [Telegram](../../src/workflow_bot.py), SQLite archive/analysis/application stores и расширение.

Проверять разрывы в [архитектуре](../architecture/current-state.md) и [gap analysis](../architecture/gap-analysis.md). Не исполнять фазы исходного ТЗ так, словно этих компонентов нет. Telegram остаётся общим мобильным пультом, а не новым отдельным агентом.

## Что развивать

- Типизированные общие request/result contracts, capability-матрица сайтов, единый task/case ID, воспроизводимые переходы и ссылки между источником, рейтингом, анализом, CV, evidence и откликом.
- Кеш с учётом content hash, нормализации, модели и dimensions; проверить текущие ключи до миграции. Переиспользовать [AnalysisStore](../../src/analysis_store.py) и [ranking](../../src/extension_ranking.py). Изменение модели не должно смешивать несовместимые векторы.
- Эксперимент отдельных представлений требований/задач/исследовательской специализации только после оценки прироста retrieval. Не пересчитывать весь архив для эксперимента без необходимости.
- Luna использовать для анализа ограниченной перспективной выборки; кеш проверять по версиям входов. Schema validation, цитаты и unknown важнее лишних числовых оценок.
- Browser Copilot: оценки на странице и отдельная панель с CV/целью, источниками и действиями; если вмешательство в DOM ненадёжно, показывать собственный shortlist. Наличие полной такой панели сейчас не утверждается.
- Планировщик должен различать запланировано, выполняется, ожидание Chrome, partial и завершено; offline/sleep не должны терять task или вызывать повторные оплаты.

## Расходы и измеримость

Отдельно учитывать embeddings, Luna, reranking, recovery, form understanding, questionnaire answering. Измерять цену полезной рекомендации и подготовленного отклика, cache hit rate, задержку и долю ручных вмешательств. Платные запуски требуют предусмотренного согласования и бюджета; копирование промпта без API остаётся доступным вариантом.

LLM применять к смыслу и неоднозначности. Хранение, валидацию, очередь, дедупликацию, retry и approvals выполнять детерминированно. Prompt injection из вакансий/чатов не может менять разрешённые действия. Сохранять timeout, отмену, контроль доменов, аудит результата и защиту секретов в текущих границах.

## Приёмка следующей итерации

Один вертикальный milestone с baseline, миграцией при необходимости, проверкой совместимости и feature flag при риске. Прогнать затронутые offline-проверки; отдельно записать результаты live-сценария и ограничения. Новые микросервисы, векторная БД, cloud runtime и полный SwiftUI rewrite требуют собственной измеримой причины, а не названия «AI-native».
