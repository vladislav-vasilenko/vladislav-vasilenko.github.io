Статус: предложение эксперимента, не готовый универсальный browser agent. Источники: [AI-native](sources/ai-native-extraction.md), [ТЗ](sources/evolutionary-career-platform.md).

## Основа

Переиспользовать [board adapters](../../hh-research-extension/board-adapters.js), [runtime](../../hh-research-extension/adapters/runtime.js), [диагностику](../../hh-research-extension/diagnostics-worker.js) и текущий worker. Сначала проверить реальные capabilities каждого сайта и доступность разрешённого API; не заменять работающий DOM-сбор ради новой абстракции.

## Предложение

Выбирать самый дешёвый надёжный путь: доступный официальный API → JSON-LD/структурированные данные → semantic DOM → существующие CSS-адаптеры → ограниченное AI recovery → visual fallback. Это варианты, а не обязательные шесть вызовов для каждой страницы.

Валидировать не только схему JSON, но и полноту: ID/URL, обязательные поля, длина описания, уникальность, пагинация и аномалии количества результатов. Различать пустую выдачу, авторизацию, сетевой сбой и изменение страницы. Возвращать полезную диагностику в вебе без утечки данных сессии.

AI recovery получает минимальный диагностический снимок, предлагает извлечение или конфигурацию, возвращает обоснование и проходит тот же validator. Автоматическое переключение допустимо между проверенными стратегиями. Изменение production-кода — через review и регрессионные fixtures, а не прямую запись LLM в адаптер.

## Первый эксперимент

Один адаптер, сохранённые разрешённые fixtures и искусственный drift: CSS-классы, вложенность, порядок, пропуск optional field, пагинация. Сравнить базовый extractor, semantic fallback и recovery. Измерять precision/recall извлечённых карточек на размеченном fixture, полноту полей, ложные успехи, задержку и стоимость восстановления.

Условие расширения: восстановление повышает полезную полноту и не принимает обрезанную выдачу за успех; бюджет, число попыток и остановка ограничены. Сравнение провести сначала offline, без новых платных вызовов по умолчанию. Доступность и условия внешних API проверить отдельно перед внедрением. Не обходить ограничения доступа; недоступность явно передавать пользователю.
