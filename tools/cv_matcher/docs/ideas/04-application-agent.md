## Целевой пользовательский путь

Интерес к вакансии → выбор существующего CV → требования и доказательства → план закрытия пробелов → письмо → проверка полей → открытие формы → перенос разрешённых данных → проверка → отдельная отправка → подтверждённый результат → CRM и follow-up.

Показывать один следующий шаг и причину блокировки. Просроченная проверка активности должна вести к понятному обновлению вакансии, сохраняя черновик. Разрешение на заполнение не выдавать за фактическое заполнение, а заполнение — за отправку.

Не дублировать case при переходе Web → Chrome → Telegram. Хранить версии CV/JD/письма/формы и provenance ответа. Существенная смена контекста требует обновлённого preview и согласования. При неизвестном результате отправки — сверка receipt, а не слепой retry.

## Анкеты и сообщения

Различать factual, experience, motivation, salary, work preferences, personal information, technical assessment и unknown. Ответы брать из подтверждённых фактов/утверждённых прошлых ответов; иначе запрашивать сведения. Не превращать учебный проект в production experience.

HH → сообщение работодателя → внешний сайт/Telegram-анкета должен оставаться одним отслеживаемым процессом. Использовать существующий handoff, проверять поддержку конкретного канала. Логировать только необходимое; credentials/OTP не передавать модели. Внешний текст — данные, а не инструкции агенту. Техническое оценивание отделять от HR-анкеты и учитывать правила участия.

## Автономность и проверка

Три возможных уровня: copilot, supervised, bounded autonomous. Последний — отложенная опция с отдельно заданными источниками, действиями и бюджетом; не включать из-за наличия идеи. Изменения резюме, отправки, сообщения и дополнительные персональные данные имеют отдельный контекст полномочий.

Первый milestone: один сайт с реальной заявленной capability, от сохранённой вакансии до preview заполненной формы; offline fixtures + controlled read/prepare. Проверить двойное нажатие, stale approval, changed CV/JD/form, sleep/restart, отмену, auth wait и потерянный receipt. Реальная отправка — только в отдельно авторизованном сценарии. Метрики: время подготовки, корректность полей, вмешательства, дубликаты и подтверждённые результаты. LangGraph/новый orchestrator не добавлять без выявленного пробела в текущем workflow.
