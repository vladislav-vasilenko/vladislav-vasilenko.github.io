# Идеи развития Career Intelligence

Собрано 20.10.2026 по трём приложенным текстам и обсуждению в чате. Это каталог предложений для следующего плана, **не запуск новой фазы**. Исходные материалы сохранены целиком; заметки ниже связывают их с существующей системой.

## Темы и предлагаемый порядок

| Порядок | Идея | С чего начать | Статус |
|---|---|---|---|
| 1 | [Качественный отклик и анкеты](04-application-agent.md) | Один поддержанный сайт: вакансия → проверенные поля → preview → проверяемый результат | Основы существуют; сквозную готовность проверять по сайту |
| 2 | [Карьерная ценность и следующий отклик](02-career-value-and-feedback.md) | Разметка релевантности и объяснимая очередь действий | Feedback и semantic ranking существуют; качество новой формулы — гипотеза |
| 3 | [Навыки, проекты и карьерная траектория](06-learning-and-evidence.md) | Один гэп → лабораторная → evidence → обновлённая рекомендация | Skills engine существует; расширение проверки доказательств — развитие |
| 4 | [Радар рынка и компаний](01-market-radar.md) | Покрытие источников и динамика одной специализации | Сбор и классификация существуют; полнота рынка не доказана |
| 5 | [Устойчивое извлечение](03-adaptive-extraction.md) | Контролируемый drift-тест одного адаптера | Адаптеры существуют; ограниченный AI recovery — эксперимент |
| Сквозное | [Архитектура, стоимость и этапы](05-evolutionary-architecture.md) | Расширять общий слой и существующее хранение | Не создавать параллельную платформу |

Порядок — предложение для обсуждения, а не жёсткая дорожная карта. Актуальная пользовательская блокировка может менять первый milestone.

## Как пользоваться будущему агенту

1. Прочитать [handoff](../handoff/2026-10-20-agent-planning-brief.md), [application layer](../architecture/application-layer.md), [gap analysis](../architecture/gap-analysis.md) и выбранную заметку.
2. Проверить соответствующие исходники: датированные документы могут отставать от последних правок.
3. Выбрать один вертикальный сценарий, зафиксировать baseline, зависимости, стоимость и критерий приёмки. Не запускать все фазы исходного ТЗ одновременно.
4. Отделять наличие кода, offline-проверку и успешный live-сценарий. Ручная отметка «Отклик сделан» не равна подтверждению отправки площадкой.

## Уточнения к исходным предложениям

- Telegram уже существует и выбран основным мобильным интерфейсом; рекомендация исходника «Telegram позже» не отменяет [ADR 0005](../architecture/adr/0005-telegram-primary-control.md).
- Общий application layer, MCP, scheduler, история, анкеты и approvals уже имеют реализации. Их не нужно добавлять заново под новыми именами.
- Актуальное semantic ranking использует векторы SQLite. Упоминание ChromaDB в старом описании не является основанием для миграции; см. [ADR 0002](../architecture/adr/0002-sqlite-and-chroma.md).
- Для Яндекса в текущем обсуждении выбран `https://yandex.ru/jobs/vacancies`. Старый адрес из исходного ТЗ сохранён только в источнике.
- Названия внешних продуктов, возможности API, лимиты и утверждения о правилах площадок из приложений не проверялись при сохранении. Проверять по официальным источникам перед реализацией.
- Семантическая близость, профессиональное соответствие, карьерная ценность и вероятность интервью — разные величины. Числа из примеров не являются измеренными результатами.
- Платные вызовы, новые внешние отправки, включение автоподнятия и перенос в облако этим документом не запускаются.
