# Вакансии по выбранному резюме — расширение 0.8.1

Повседневный цикл: загрузить резюме → выбрать поиск → собрать вакансии →
выбрать CV → получить топ‑10 в расширении. Для каждого анализа запускать Python
командой не нужно. Один локальный сервис обслуживает импорт файлов и OpenAI.

## Обновить расширение

В `chrome://extensions` перезагрузить ML Research Vacancy Search.
Если установлено из архива, сначала заменить файлы в его распакованной папке.
Исходная папка проекта:

```text
/Users/vladmac/Code/Bots-Automation/Node-Tools/NodeJS/Misc-Projects/vladislav-vasilenko.github.io/tools/cv_matcher/hh-research-extension
```

Открывать расширение кнопкой на панели **Google Chrome**. Открытый как файл
`popup.html` не имеет доступа к Chrome Extension API.

## Подключить локальный сервис один раз на сеанс

Из папки проекта:

```sh
cd /Users/vladmac/Code/Bots-Automation/Node-Tools/NodeJS/Misc-Projects/vladislav-vasilenko.github.io/tools/cv_matcher
.venv/bin/python resume_import_server.py
```

Для embeddings задать `OPENAI_API_KEY` в локальном `.env` проекта до запуска.
При изменении ключа перезапустить сервис. Вкладки расширения не получают этот
ключ. Сервис слушает только `127.0.0.1:8788`; код подключения находится в
`.cache/resume_import/token.txt`. Он отдельный от ключа OpenAI.

Открыть в расширении «Ранжировать по выбранному резюме» →
«Подключение локального сервиса», вставить **локальный код**, нажать
«Подключить сервис». Chrome запросит разрешение на localhost.
Код хранится в `chrome.storage.session` до завершения сеанса браузера.
Подключение также доступно в управлении резюме. TXT/MD и сбор HH работают без сервиса.

## Загрузить все резюме HH

1. Открыть [каталог HH](https://hh.ru/applicant/profile/me) в Chrome с вашим входом.
2. Нажать кнопку расширения → «Загрузить актуальные резюме из каталога».
3. Дождаться результата: расширение последовательно откроет все заполненные
   резюме и вернёт вкладку к каталогу. Popup можно закрыть.
4. Вновь открыть расширение и сверить число найденных, загруженных и ошибок.

Ограничения старым списком из трёх CV больше нет. Пустые черновики пропускаются.
Ошибка одного CV показана отдельно. Основное резюме не меняется от порядка
карточек; если оно исчезло, нужно выбрать другое в «Управление резюме».
Все найденные CV загружаются без LLM-вызовов.

Снимки HH и Google Docs для анализа действуют 24 часа. После правок на сайте
обязательно перечитать CV: возраст снимка сам по себе не обнаруживает изменения
на сервере. Файлы считаются неизменяемыми снимками; обновляются новой загрузкой.

## Google Docs и файлы

Открыть «Управление резюме / импорт файлов и Google Docs».

- Google Docs: вставить ссылку, открыть документ в Chrome, в его вкладке нажать
  кнопку расширения → «Прочитать Google Docs открытой вкладки». При первом чтении
  Chrome запросит доступ к `docs.google.com` и `*.googleusercontent.com` — доменам
  документа и его текстового экспорта. Для закрытого документа нужен Google-вход
  с доступом. Экспорт не обходит ограничения владельца.
- Файл: выбрать один или несколько `.pages`, `.doc`, `.docx`, `.txt`, `.pdf`, `.md`.
  TXT/MD читаются браузером; остальные — локальным сервисом. До 12 МБ на файл.
- Сверить текст в preview, при необходимости исправить название/текст, нажать
  «Подтвердить текст и сохранить резюме». Файлы из очереди проверяются по одному.
- «Сделать основным» задаёт CV по умолчанию. Для разового ранжирования можно выбрать
  другое резюме на странице рейтинга, не меняя основное.

PDF должен содержать текст; для сканов предварительно нужен OCR. PDF до 40 страниц.
Старый DOC читается через macOS `textutil`. Pages: поддерживаются XML и IWA-текстовые
блоки, но сложные таблицы/текстовые блоки требуют сверки полноты и порядка. Если
текст потерян, экспортировать DOCX/PDF из Pages. Превью-картинка не выдаётся за CV.
Если Google Docs не отдаёт TXT или требует вход, можно скачать TXT/DOCX через
меню документа и загрузить файл. Импорт сам по себе не вызывает OpenAI.

## Собрать вакансии HH с пагинацией

1. В popup выбрать уровень, компанию, направление и географию. Huawei R&D — Top-Tier;
   Яндекс и Сбер остаются главными приоритетами поиска. Москва и удалённо по России
   — отдельные поиски. Зарплата без фильтра. На первом проходе период выключен.
2. Нажать **«Открыть поиск HH»**. Для одновременного обновления каталога из вкладки HH
   есть отдельная кнопка «Обновить все резюме HH и открыть поиск».
3. В открытой выдаче снова нажать расширение, задать лимиты и нажать
   **«Собрать выдачу HH с пагинацией»**.
4. Расширение прочитает ссылки со страниц выдачи, затем последовательно откроет
   вакансии и сохранит полные требования. Прогресс виден при повторном открытии popup.
   Кнопка «Остановить сбор HH» сохраняет уже прочитанное.

По умолчанию: 5 страниц, 50 полных описаний; максимум 20/200 за запуск. Время —
до 4 минут. Свежие полные описания, прочитанные за последние 24 часа, повторно
не открываются. Обычный конец — отсутствие следующей ссылки в доступной пагинации;
при ошибке/лимите сохранён частичный результат. Для продолжения — следующая
страница или повторный запуск: свежие описания будут пропущены.
Проверку HH/вход выполняет пользователь, после неё сбор запускается заново.
Не закрывать и не переключать адрес рабочей HH-вкладки во время обхода.

JS-скрипты расширения читают DOM и переходят через Chrome API. Для этого сценария
не запускаются Playwright/Selenium и не используется публичный HH API.

Корпоративные сайты Avito/Ozon: открыть список или полную вакансию и нажать
«Сохранить вакансии открытой вкладки». Автообход HH не распространяется на их
пагинацию. Для нового job board используются JobPosting/CSS-настройки и сверка
`needs_review` перед подтверждением. Универсальное распознавание любого сайта
без настройки не гарантируется. [Huawei](huawei_search.md).

## Получить рейтинг прямо из расширения

1. В popup выбрать CV в поле «Резюме» и нажать
   **«Ранжировать по выбранному резюме»**.
2. На странице рейтинга проверить CV, выбрать `text-embedding-3-small` либо
   `text-embedding-3-large`. Необязательная цель позволяет добавить контекст
   Research Engineer / Generative Modelling / DiT / Transformer training.
3. Подключить локальный сервис, если ещё не подключён.
4. Нажать **«Ранжировать через OpenAI»** и оставить страницу открытой до результата.

В OpenAI передаются выбранный профессиональный CV, полные описания и введённая
цель. Остальные резюме не отправляются. По умолчанию рейтинг отражает семантическую
близость к CV; с целью — 80% CV + 20% цель (начальная эвристика). Максимум 200
самых свежих сохранённых вакансий за расчёт, лимит можно уменьшить; по умолчанию показываются первые 10. Поле «Сколько вакансий показать» меняет видимое количество (1–200); кнопка «Показать все рассчитанные вакансии» раскрывает весь рассчитанный список. Изменение показа не вызывает API. Сохранённый расчёт для той же версии CV восстанавливается при повторном открытии страницы. Компания учитывается при выборе выдачи,
а не добавляет скрытый бонус числовой близости. Векторы разных моделей не смешиваются.

Результат показывает название использованного CV, модель, количество новых API
запросов/токенов и близкие текстовые фрагменты. Embeddings отдельных неизменившихся
фрагментов CV/JD повторно не оплачиваются: они берутся из `.cache/extension_embeddings`.
Смена CV пересчитывает сравнение с теми же векторами вакансий; правки CV/JD создают
новые версии затронутых фрагментов. Кнопка экспорта сохраняет рейтинг в JSON.

Сходство не является процентом соответствия или вероятностью найма. По embeddings
нельзя достоверно перечислить недостающие обязательные требования и решить
«стоит ли откликаться»: подробный разбор доступен в существующем LLM-пайплайне
или в чате. Отклики и сообщения расширение не отправляет. Ежедневного расписания нет.

## Экспорт и расширенный Python-анализ

Резюме: «Экспортировать резюме для Python» → `resumes.json`.
Вакансии: «Экспортировать JSON» → `vacancies.json`.
Рейтинг: «Экспортировать рейтинг» → `vacancy-ranking.json`.

Для отдельной LLM-оценки и комментариев (нужны настроенные embeddings и LLM):

```sh
.venv/bin/python cv_matcher.py --resume-source bundle --resume-bundle "/absolute/path/resumes.json" --vacancies-json "/absolute/path/vacancies.json" --top-k 40
```

Облачный режим существующего пайплайна добавляется явно через `--use-openai`.
Его стоимость и настройки отличаются от простого embeddings-рейтинга расширения.
`--hh-resumes` оставлен как совместимый алиас. Результаты хранятся локально
в `.cache/hh_matching`, вне публичной папки сайта. Резервные CV в CLI автоматически
сравниваются только с локальными embeddings; в облачном режиме используется основное.

Официальные описания:
[embeddings](https://developers.openai.com/api/docs/guides/embeddings),
[API authentication](https://developers.openai.com/api/reference/overview#authentication).


## Короткий сопроводительный текст

В рейтинге у каждой вакансии нажать «Сопроводительный текст». Используются именно
CV, по которому построен этот рейтинг, и полное актуально сохранённое описание
выбранной вакансии. При изменении версии CV сначала пересчитать рейтинг.

Перед генерацией раскройте «Настроить письмо: комментарий и длина» в карточке.
В «Мои пожелания к письму» можно описать мотивацию, интерес к направлениям и
желаемые акценты. Выберите от 1 до 50 предложений основного текста; приветствие и
завершение добавляются отдельно. По умолчанию — 2 предложения, до 50 слов / 480
символов на всё письмо; при большей длине лимит увеличивается. Оценка времени
чтения показывается по фактическому объёму. Длинное письмо разбивается на абзацы,
поле для чтения увеличивается; для генерации выделяется больше времени и токенов.
Затем нажмите «Сопроводительный текст».

Опыт подтверждается выбранным CV, а личные интересы могут опираться на ваш
комментарий. Комментарий не превращает интерес в коммерческий опыт. Модель
должна связать мотивацию с конкретной вакансией и не повторять непроверенные
подробности об устройстве сторонних моделей. Текст можно отредактировать и
скопировать. Под ним раскрывается «Источники: опыт и мотивация»: фрагменты CV,
вашего комментария и вакансии с указанием источника.
Планы/учебные проекты должны сохранять эти оговорки; неподтверждённые цитаты,
цифры и технологии отклоняются. Смысловую точность всё равно сверять по источникам
перед отправкой: проверка цитат не доказывает все нюансы перефразирования.

Генерация выполняется только по кнопке, отдельно от embeddings-ранжирования,
через тот же локальный сервис с OPENAI_API_KEY. Модель по умолчанию gpt-4.1-mini;
опционально задаётся на сервере через COVER_LETTER_MODEL в .env и перезапуск сервиса.
Ключу нужен доступ к Responses API выбранной модели. Повтор для тех же версий
CV/JD, модели, промпта, комментария и числа предложений берётся из .cache/cover_letters
без нового API-запроса. Изменение настроек само по себе не вызывает API: нужен клик
по кнопке генерации. При возврате к варианту на открытой странице сохраняются и
ручные правки; после закрытия страницы вручную исправленный текст нужно сохранить
самостоятельно. Смена CV, описания вакансии или модели создаёт новый черновик. Не все ошибки
можно автоматически исправить: отклонённый текст не сохраняется и не подменяется
выдуманным опытом. Обновление модели/текста требует нового запроса по кнопке.

Расширение не отправляет письмо работодателю. «Скопировать текст» копирует только
короткий черновик без цитат. После обновления до 0.5.3 нужно перезапустить локальный
сервис; существующий код подключения token.txt сохраняется.
# Рекомендации HH для того же CV и карьерной цели · 0.5.4

Выберите резюме HH → заполните «Карьерная цель для сравнения» →
«Открыть рекомендации HH для этого CV». В открывшейся вкладке снова нажмите
значок расширения и «Собрать рекомендации HH с полными описаниями».
Лимиты страниц/описаний задаются перед запуском; после остановки данные остаются.

После сбора нажмите «Сравнить рекомендации HH с этим CV и целью».
Откроется рейтинг с тем же CV, введённой целью и подборкой рекомендаций для него.
Запустите «Ранжировать через OpenAI»; в расчёт попадут только полные описания.
Число показанных результатов можно изменить без нового API-запроса.
В карточке «Сопроводительный текст» создаёт редактируемый черновик выбранной длины.

Если рекомендации ещё не содержат полных JD, кнопка сравнения выключена:
сначала дождитесь загрузки описаний. Для продолжения большого списка откройте
нужную страницу и повторите сбор. При смене CV рекомендации собираются отдельно;
уже загруженные свежие полные описания повторно не открываются.


## Скопировать CV и вакансию для ChatGPT App · 0.6.3

В карточке рейтинга нажмите **«Скопировать CV + вакансию для ChatGPT»**. Вставьте
скопированный пакет в новый чат ChatGPT App. Он содержит профессиональные разделы
именно выбранного CV, полное сохранённое описание этой вакансии, цель поиска,
даты/версии источников и промпт для сравнения. Другие CV и вакансии не копируются.
Копирование работает локально без OpenAI API и без подключения Python-сервиса;
готовый сохранённый рейтинг можно открыть без нового расчёта.

При необходимости сначала раскройте **«Для ChatGPT: добавить пожелания или вопрос
рекрутера»**. Можно добавить пожелания к анализу (до 4000 символов) и вопрос HH,
ИИ-рекрутера или переписку с вашим черновиком ответа (до 16000 символов). Затем
скопируйте пакет заново. Пожелания сохраняются при изменении числа показанных
вакансий на открытой странице, но не после её закрытия.

Промпт запрашивает таблицу требований/подтверждений/пробелов, рекомендацию по
отклику, план подготовки и уточняющие вопросы. Он отличает коммерческий опыт от
учебного и самостоятельного, а отсутствие навыка в CV — от отсутствия самого навыка.
Следующие вопросы формы HH или ИИ-рекрутера присылайте в тот же чат ChatGPT:
контекст пары CV–вакансия уже будет там. Все предлагаемые ответы — черновики.

Пакет можно просмотреть под карточкой. При отказе доступа к буферу появится
выделенное поле для Cmd+C / Ctrl+C. Текст не обрезается. Проверка версии CV не
подменяет обновление на сайте: если редактировали резюме в HH/Docs, сначала
обновите его через расширение и пересчитайте рейтинг. Известные email/телефоны
маскируются; источники HH изначально содержат только профессиональные разделы.
Автоматической отправки пакета в ChatGPT или работодателю нет.
