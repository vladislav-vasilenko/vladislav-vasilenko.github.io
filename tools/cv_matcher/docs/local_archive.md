# Локальный архив и embeddings

Один сервис `resume_import_server.py` обслуживает расширение и сайт http://127.0.0.1:8788/. Резюме, вакансии, версии, наблюдения выдачи, рейтинги и векторы хранятся в общей SQLite-базе `.cache/applications/state.sqlite3`, рядом с существующей очередью откликов. Дополнительные сервисы и зависимости не нужны.

## Как пользоваться

1. Запустите локальный сервис. После обновления файлов расширения перезагрузите **ML Research Vacancy Search** на `chrome://extensions` (версия 0.8.1).
2. В расширении откройте **«Локальный архив · сайт и синхронизация»**. При необходимости введите код из `.cache/resume_import/token.txt`.
3. Нажмите **«Синхронизировать весь сохранённый набор»**. Это перенесёт все сохранённые CV, карточки и полные описания, наблюдения поисков, выбранную цель и последний сохранённый рейтинг. Включённая автосинхронизация сохраняет следующие изменения и рейтинги. Если сервис выключен, снимки остаются в очереди до подтверждённого сохранения.
4. Нажмите **«Открыть сайт анализа и истории»**. Ссылка подключения одноразовая; ключ OpenAI не передаётся сайту. После перезапуска сервера потребуется повторное подключение.
5. На сайте выберите CV и embedding-модель. По умолчанию отображаются полные описания. Подходящий сохранённый рейтинг сортирует вакансии по близости к этому CV и цели; просмотр не вызывает модели. В карточке доступны текст, история, локальные подсказки по терминам и копирование CV + вакансии с промптом для ChatGPT.

## Что означает статус embeddings

Статус есть у каждой вакансии и относится к выбранной модели:

| Статус | Значение |
| --- | --- |
| Рассчитаны | В SQLite есть все фрагменты текущего названия и описания |
| Частично рассчитаны | Есть только часть фрагментов; например, расчёт прервался |
| Не рассчитаны | Для этого текста и модели пока нет привязанных векторов |
| Требуют обновления | Векторы есть для предыдущего текста, текущий текст изменился |
| Нужно полное описание | Сохранена только карточка или непроверенный фрагмент |

Количество готовых фрагментов и модель показаны в карточке. Фильтр позволяет найти нужный статус. Переключение `3-small` / `3-large` ничего не вычисляет автоматически.

Embeddings вычисляет Python по явному нажатию **«Ранжировать через OpenAI»** в расширении. Векторы сразу записываются в SQLite как float32 BLOB с моделью, размерностью, namespace и хэшем нормализованного текста. Одинаковые фрагменты не дублируются для каждой пары CV–вакансия. Таблица привязок связывает документы и их версии с векторами; отдельная таблица сохраняет каждый рейтинг, оценки пар, выбранный CV и его хэш, цель, модель и дату. Изменение CV не требует повторно вычислять неизменившиеся описания вакансий.

Старый файловый кэш `.cache/extension_embeddings` читается и переносится без API при запуске сервиса и синхронизации. Старые файлы сохраняются как резерв; новые векторы этого сценария записываются только в SQLite. Если данные из расширения не содержат самих векторов, рейтинг не используется как доказательство наличия векторов: статус определяется содержимым базы.

Рейтинг применяется только при совпадении версии CV, модели, цели и текста вакансии. Для старого результата без хэша вакансии дополнительно требуется точное совпадение даты исходного снимка. Число близости не является процентом соответствия или вероятностью найма. Более старые рейтинги, которые браузер уже перезаписал до включения синхронизации, восстановить невозможно.

## История и исчезновение

Первая синхронизация создаёт исходные версии, а не выдуманную историю. Начальный импорт не засоряет ленту сотнями событий «добавлено». Изменения текста создают новые версии; повторная проверка без правок — нет. Поздние офлайн-снимки пополняют историю и не затирают более новые данные.

«Не найдена в поиске» относится к конкретной выдаче и её фильтрам. Такой вывод допустим только после полного обхода с первой до последней страницы. Прерванный сбор, лимит страниц, CAPTCHA и старые снимки без признака полноты не доказывают исчезновение. Исчезновение из каталога CV сохраняет само CV и его историю в архиве.

«Закрыта на HH» требует явного признака архива на странице самой вакансии. При полном сопоставимом обходе сборщик перепроверяет до 20 исчезнувших полных вакансий в пределах общего лимита запуска. Это не обеспечивает мгновенную проверку всех 917 записей и не распространяется автоматически на все сторонние boards.

## Хранение и восстановление

Архив доступен только через loopback и код подключения; сайт получает ограниченную cookie-сессию для чтения и локального сравнения, с отдельной явной кнопкой платного разбора Luna, без доступа к ранжированию и отправке откликов. API-ключ остаётся в `.env` сервиса. Chrome хранит сборы, очередь синхронизации и последний рейтинг; базой истории и векторов служит SQLite.

«Восстановить данные из локального архива» объединяет актуальные CV, вакансии, цель и последний рейтинг с браузерными данными. Векторы остаются на сервере и не копируются обратно в Chrome. «Скачать резервную копию» экспортирует также историю рейтингов, привязки и сами векторы (base64 float32 little-endian). Автоматического импорта этого JSON пока нет; для полной переносимой резервной копии SQLite остановите сервис и сохраните файл базы. Не размещайте базу и выгрузки в публичном репозитории.


## Разбор Luna и история разборов резюме

В карточке полной вакансии **«Разобрать требования · Luna»** выполняет подробное сравнение с выбранным CV и целью. При открытии карточки сначала читается SQLite; платный запрос не запускается сам. Ключ повторного использования — ID и хэши профессиональных текстов CV/вакансии, цель и модель. Обновление внутреннего промпта само по себе не заставляет повторно оплачивать неизменённую пару. Изменение цели может потребовать отдельного разбора, поскольку рекомендация зависит от неё.

Результат, цитаты, вопросы, рекомендации и проценты сохраняются в `skill_analyses`. `skill_analysis_sources` хранит точные профессиональные тексты, переданные модели, и ссылки на неизменяемые записи `versions`. Снимки исходных документов уже содержатся в SQLite. Контакты исключаются. Если синхронизация пришла во время генерации, результат всё равно связан с текстами, реально отправленными модели.

Раздел **«История разборов резюме»** показывает все сохранённые результаты с фильтром по CV, датой, целью, моделью, версией промпта и номерами исходных версий. Внутри раскрываются CV и вакансия с SHA-256 и указанием, совпадает ли текст с текущим. Старые результаты не затираются новыми. Исторический просмотр не обращается к OpenAI. Прежние разборы связываются с архивными версиями по точному хэшу модельного текста; если источник не найден, это явно указано, актуальный текст вместо старого не подставляется. Резервная выгрузка содержит результаты и исходные тексты.

Проценты означают покрытие выделенных требований подтверждениями в CV. Практика = 1, частичное подтверждение = 0,5, изучение = 0,25, нет подтверждения/явный пробел = 0; обязательные требования имеют двойной вес. Направления: теория, методы ML, исследования, инженерия, продакшен, уровень ответственности. Пустые направления не получают фиктивные 100%. Это не вероятность найма и не объективное измерение навыка. Рекомендации модели и интерпретацию цитат стоит проверять.

Пошаговый интерфейс, фильтр компаний и отметки на HH описаны в [workflow_and_adapters.md](workflow_and_adapters.md).
