> Сверка 22.10.2026. Дополнительно доступны [траектории](architecture/career-trajectory.md) и [разбор нескольких CV](architecture/resume-portfolio-review.md). API/offline режим относится к конкретной операции, не ко всей системе; semantic score не является вероятностью найма.

## Начать работу

Обновите страницу локального сервиса. В Chrome → `chrome://extensions` перезагрузите ML Research Vacancy Search, затем обновите страницы HH и открытый рейтинг расширения. Исходная папка расширения — `hh-research-extension` внутри проекта `cv_matcher`; актуальная копия и ZIP также лежат в Documents/AI Vacancies Replies. Перезапуск расширения нужен для новых обработчиков вопросов без API.

## Вакансии и рейтинг относительно CV

В веб-сервисе теперь есть отдельный раздел **«Рейтинг по резюме»**. Ранее сохранённые оценки были видны внутри «Вакансий», а история запусков — в «Изменениях». Новый раздел использует ту же SQLite и те же векторы, что расширение.

1. Выберите CV над списком. Сравнивается только это резюме.
2. Найдите компанию и выберите её в фильтре. Поиск по компаниям сужает варианты, сам выбор применяет фильтр. Варианты работодателя Сбера объединяются в группу «Сбер».
3. Проверьте цель и embedding-модель.
4. Выберите действие:
   - **Показать сохранённый рейтинг · без API** — только чтение SQLite.
   - **Рассчитать из готовых векторов · без API** — локальное сравнение. Если каких-то векторов не хватает, расчёт останавливается с объяснением, без перехода к платному режиму.
   - **Рассчитать / обновить · API embeddings** — недостающие векторы загружаются из OpenAI; готовые сравнения и векторы используются повторно.

Фильтр компании есть и в обычном разделе «Вакансии». Подтверждённо закрытые позиции исключаются из нового расчёта и экрана рейтинга. Неизвестная активность не равна подтверждённой открытости: перед откликом её проверяет HH-вкладка.

Кэш сравнения привязан к CV, его версии, тексту вакансии, цели и модели. Изменение компании само по себе не делает уже рассчитанную пару устаревшей. За один запуск — до 200 полных вакансий: для большей подборки нужно сузить компанию. Просмотр и пагинация не вызывают OpenAI. Близость текстов не является процентом навыков или вероятностью найма.

Проверка на реальной базе: группа «Сбер», выбранное основное CV и текущая цель — 165 вакансий из кэша, новых сравнений 0, API-запросов 0.

## Через API и без API

Оба варианта предусмотрены для разбора требований, сопроводительного письма, редакторского диалога и ответов на вопросы HH / Giga. Промпт включает выбранное резюме, полную вакансию, цель и относящиеся к действию пожелания. В редакторском диалоге также включаются история, последнее сообщение и текущая редакция письма, если отмечена галочка. Вопросы Giga получают историю предыдущих утверждённых ответов.

**Через API:** нажмите явную кнопку генерации, проверьте результат и отредактируйте его. Чтение сохранённого результата само генерацию не запускает.

**Без API:** скопируйте промпт, вставьте в ChatGPT App или другой выбранный чат и верните готовый текст в форму. Оплата ChatGPT и доступность используемого чата определяются вашей подпиской; наш сервис при копировании не вызывает API модели.

- Разбор навыков возвращается полным JSON по схеме из промпта. Проверяются формат, ID и цитаты источников; результат сохраняется с исходными версиями в SQLite.
- Письмо возвращается обычным текстом. В CRM сохраните редакцию. На HH используйте отдельную кнопку переноса в поле.
- Ответ на вопрос возвращается текстом в соответствующее поле анкеты. Проверка и разрешение отправки остаются отдельными действиями.
- В Telegram длинный промпт выдаётся файлом `prompt-chatgpt.txt` после нажатия кнопки. В Giga-диалоге можно сначала задать пожелания, затем выбрать «Ответ без API» и прислать результат боту. Он сохранится черновиком с отдельной кнопкой отправки.

На HH в панели доступны «Через API / Без API», а при выделении вопроса — генерация и «Ответ без API». В рейтинге расширения есть отдельная кнопка письма без API с теми же пожеланиями и длиной 1–50 предложений.

## Этап и состояние работы

Этапы: **Подготовка → Отклик отправлен → Пройдено интервью с AI-рекрутером → Общение с рекрутером → Первый / Второй / Третий этап → Отказ / Оффер**. Промежуточные этапы можно пропускать: это не обязательный маршрут каждой компании.

Независимое состояние: **Готовлюсь / Ждём ответа / Ждём приглашения на интервью / Интервью назначено / Завершено**. Дополнительно указываются следующий шаг и срок его выполнения или проверки ответа.

При выборе AI-интервью предлагаются «Ждём приглашения» и следующий шаг «Дождаться приглашения на интервью с командой». Можно изменить их до сохранения. Подтверждённая HH отправка переводит подготовку в «Отклик отправлен», но не откатывает ручные этапы собеседований. Ручной этап и наблюдаемый HH-статус сохраняются раздельно.

Сохранение плана проверяет его версию: параллельная правка из Telegram не будет молча затёрта браузером. История сохраняется в SQLite и отображается в карточке. Фильтры откликов работают по этапу и состоянию.

В Telegram: `/hh` → отклик → «Этап отбора», «Состояние работы», «Следующий шаг» или «Назначить интервью». Формат ввода времени указан в ответе бота. Сроки по умолчанию — Москва. При наступлении срока бот один раз напомнит о следующем шаге; о назначенной встрече — в течение часа до начала. Напоминания требуют работающего бота и компьютера.

## Интервью и Google Calendar

В карточке отклика можно назначить несколько встреч: название, этап, начало/окончание, часовой пояс, адрес или ссылка и план подготовки. Встречи видны на экране «Сегодня». Перенос использует ту же запись и сохраняет предыдущие версии. Статус встречи: назначена / состоялась / отменена. Он не меняет автоматически этап отбора.

Без OAuth доступны `.ics` и ручное открытие Google с заполненными полями. Ручное добавление не создаёт синхронизацию, и повторное добавление может дать дубликат.

Для подключения API Google:

1. В Google Cloud включите Google Calendar API и настройте OAuth consent screen. Для приложения в режиме Testing добавьте свой аккаунт в test users.
2. Создайте OAuth-клиент типа **Web application**. Зарегистрируйте redirect URI: `http://127.0.0.1:8788/archive/calendar/callback`.
3. В локальном `.env` задайте `GOOGLE_CALENDAR_CLIENT_ID` и `GOOGLE_CALENDAR_CLIENT_SECRET`, затем перезапустите Python-сервис.
4. В карточке встречи нажмите «Подключить Google Calendar» и завершите вход Google.
5. Нажмите «Синхронизировать с Google Calendar» у конкретной встречи.

Источники протокола: [OAuth для веб-приложений](https://developers.google.com/identity/protocols/oauth2/web-server), [создание события с заданным ID](https://developers.google.com/workspace/calendar/api/v3/reference/events/insert), [частичное обновление события](https://developers.google.com/workspace/calendar/api/v3/reference/events/patch).

Сервис работает с основным личным календарём и своими связанными событиями. Идентификатор события стабилен; перенос обновляет его. При изменениях в Google проверяется etag — календарь не перезаписывается молча. «Получить дату / место из Google» переносит время, часовой пояс, место и отмену обратно в CRM; название и заметки остаются локальными. Если обе стороны изменены, замена локальных даты/места/статуса требует отдельного подтверждения. Предыдущая версия остаётся в истории.

Синхронизация запускается **явными кнопками**, фоновых Google push-уведомлений или периодического опроса нет. События создаются без участников и приглашений рекрутеру. Токены Google лежат в закрытом `.cache/calendar/oauth.json`, не передаются расширению и не включаются в резервную копию SQLite. После перезапуска сервиса незавершённый OAuth-вход нужно начать заново.

Реальный вход Google и создание события не проверялись: OAuth-параметры пока не настроены и даты интервью не были предоставлены. Создание, повтор после сбоя, перенос, конфликты и получение отмены проверены на тестовом транспорте без обращения к Google.
