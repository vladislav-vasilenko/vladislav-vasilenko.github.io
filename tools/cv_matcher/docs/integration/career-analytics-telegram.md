## Аналитика

GET `/archive/analytics` защищён существующим кодом подключения или cookie-сессией. [`career_analytics.snapshot`](../../src/career_analytics.py) читает текущие entities, версии, события закрытия/повторного открытия, сохранённые оценки и CRM. Не запускает модель или crawler.

[`career-charts.js`](../../archive-web/career-charts.js) строит Sankey с сохранением количества записей между соседними столбцами. Каждый поток хранит точные ID. Неизвестный разбор и отсутствие зафиксированного отклика выделены отдельно; это не отказ. Одна вакансия с двух площадок считается двумя записями, пока пользователь не выбирает группирование отдельно.

[`career-analytics.js`](../../archive-web/career-analytics.js) связывает диаграммы и список карточек общими фильтрами. «Мой фокус» включён по умолчанию: Pretraining, Post-training, Diffusion / Flow Matching, CUDA, Apple MLX / MPS / Metal, DL Engineering / Research. Совпадение любого выбранного тега включает запись один раз, даже если её основная категория другая. Флажки сохраняются в браузере, не меняют CV/цель/рейтинг. Можно выключить фокус и увидеть весь архив.

«Не классифицировано» означает, что правила не нашли признаки заданных направлений, в том числе из-за краткого описания. Это не вывод о качестве позиции. Интерфейс показывает число неполных карточек. Теги сопровождаются исходным фрагментом текста. Это прозрачная эвристика, не семантическая классификация LLM.

Apple-тег требует MLX либо технического контекста MPS/Metal. `bare-metal`, `bare metal`, физический `metal conductor`, NVIDIA MPS и ноутбук в бенефитах сами по себе не подходят. Общие слова «исследователи» в маркетинге/тексте инфраструктурной вакансии не означают DL Research. Правила выделяют блок задач/требований, если его заголовок распознан.

Карта: X — покрытие требований текущим Luna-разбором по опубликованной рубрике; Y — косинусная близость к карьерной цели. Требуются совпадающие версии CV/JD/цели. Embedding не выдаётся за подтверждение навыков, неизвестные оценки не заменяются нулём. Обучение MIT / Flow Matching показано отдельно; изучение имеет вес 0.25 в существующей рубрике. GitHub-ссылки — ссылки на доказательства из CV, а не автоматический аудит кода.

Market Evolution использует полученные на конкретную дату версии и только явные события закрытия/открытия. Неполная выдача не закрывает вакансии. При истории короче двух месяцев отображается объяснение вместо выдуманной динамики. Доступны количество и доля. Изменение долей не трактуется как переход объектов между профессиями.

### Ограничения аналитики

- Выборка не равна всему рынку; её динамика зависит от охвата сбора.
- Зарплаты пока не сохраняются структурированно: фильтр отключён, размер точек одинаковый. Цвет — специализация, не выдуманный рост спроса за 30 дней.
- Автоматического аудита GitHub и достоверной численной позиции человека на шкале Research Scientist нет.
- Исторические распределения пересчитываются текущими правилами по полученным тогда текстам; это не исторические выводы модели.

## Telegram

[`CareerApplication.candidates`](../../src/career_application.py) использует тот же `ArchiveStore.entities` и порядок current-version рейтинга, что веб: основной CV, сохранённая цель, 3-small, все компании, полные описания, без подтверждённо закрытых. Из топа исключены подтверждённые отклики из HH/CRM и пользовательская отметка «Не моё» для текущей версии CV. Черновик не считается отправленным откликом.

Основная подборка — до десяти лучших записей из полного рейтинга, а не только последнего crawl. Больше нет скрытого порога 0.45, company-tier перестановки, суточного лимита десять суммарно и отсечения по 30-минутной проверке/локации. Явные условия запроса (компании/период) сохраняются. Активность проверяется перед подготовкой/отправкой; эта защита не ослаблена. Повтор одного завершения digest не создаёт повторные сообщения, но каждый слот 10:00 / 19:00 может показать свою подборку.

[`telegram_ranking.py`](../../src/telegram_ranking.py) добавляет «Топ-10 без откликов» в меню и полный рейтинг с перелистыванием. Полный рейтинг также показывает уже существующие отклики, как веб, и явно подписывает контекст. ⭐ сохраняет пометку, но не меняет порядок по близости.

[`telegram_analysis.py`](../../src/telegram_analysis.py) даёт кнопку «Подробный разбор» прямо из подборки и «Почему подходит». Чтение результата/выбор режима не создаёт application, письмо или browser command. Сохранённый разбор открывается без API; новый — явной кнопкой Luna с пояснением передачи данных и стоимости, либо через offline prompt + JSON import. Требования, статусы, цитаты CV/вакансии и следующие шаги показываются страницами. Общий application layer сохраняет защиту версий, владельца, кэш и запрет автоматического повтора неоднозначного платного вызова.

## Обновление 20.10.2026: режимы карты, топ-50 и диагностика

- Карта переключается между cosine CV × цель (готовые embeddings, по умолчанию) и покрытием требований Luna × цель. Переключение локальное, неизвестные значения не подменяются нулём. Фильтры общие; прежние Luna-фильтры остаются явными.
- `luna_batch.py` использует таблицу `analysis_batches` в той же SQLite. POST `/archive/analytics-batch` создаёт предпросмотр до 50 лучших из текущего сохранённого рейтинга и фильтров. Список привязан к версиям CV/JD и цели; подтверждение платного запуска действует 15 минут. Только отдельная owner-кнопка переводит пакет в очередь. Обработка идёт по одному разбору через общий CareerApplication и существующий scheduler, с сохранением каждого результата. Просмотр/копирование не включает API в настройках поиска.
- Есть pause/resume/cancel в общей очереди `/tasks`. Текущий запрос завершается перед паузой/отменой. Неудачные/прерванные попытки автоматически не повторяются; продолжение обрабатывает оставшиеся записи. При остановленном backend работа ждёт его запуска; сама SQLite ничего не исполняет.
- Экспорт без API содержит CV один раз, цель, полные вакансии и R/J-источники. Возвращённый JSON импортируется через существующую строгую проверку цитат и схемы; чужие export_id, изменённые версии и закрытые вакансии отклоняются. Сохранённые разборы появляются на карте Luna.
- `CareerBatch is not defined` исправлено: модуль определён в том же загружаемом аналитическом asset до обращений к нему. Веб-интерфейс показывает раскрываемую диагностику и кнопку копирования: операция, endpoint без query, HTTP-статус, request ID, тип/stack ошибки. Секреты в URL маскируются, тело запроса не включается. Ошибка JavaScript больше не трактуется как необходимость входа.
- Изолированные проверки: **327 Python / 301 JavaScript**, успешно. Добавлены batch negative paths, воспроизведение отсутствующего компонента и сохранение диагностики после старых notice-обработчиков.
- Работающий backend и бот обновлены, health API 13 подтверждён. Живой API: предпросмотр 50 записей, 6 разборов в кэше, до 44 новых; экспорт 50 записей, 227672 символа. **Платный запуск не подтверждался, API моделей не вызывался, отклики не отправлялись.**
- Новая живая проверка через Chrome не выполнена: инструмент управления браузером был отклонён автоматической проверкой доступа из-за лимита. Это ограничение проверки UI, а не подтверждение её успешности.

### Проверка причин «Не классифицировано»

В текущей базе 1996 записей, из них 1124 без совпадения текущих правил: 805 snippet, 317 full, 2 needs_review. У 300 из 317 полных есть все актуальные векторы 3-small; у 17 нет. Простой CV score не определяет специализацию. Следующее обоснованное расширение: отдельное состояние недостаточного текста, более широкая таксономия (Data Engineering/Backend/QA/Management и др.), затем проверяемый классификатор по примерам и сохранённым embeddings с отказом при неоднозначности. Для Apple/CUDA/редких research-методов нужны проверяемые признаки в требованиях, чтобы не возвращать false positives bare-metal и рекламных блоков. Это предложение, классификатор embeddings ещё не внедрён.
