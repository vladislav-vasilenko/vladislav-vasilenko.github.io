# LinkedIn: адаптеры профиля и вакансий

**Статус: следующий этап, спецификация 22.10.2026.** Пользователь запросил управление собственным профилем и сбор рекомендаций из активной сессии Chrome. В основном расширении 0.11.22 пока нет LinkedIn host permission, профильного adapter или worker этой capability. Старый [Python scraper](../../src/scrapers/linkedin.py) не решает этот сценарий. Живая разметка авторизованного LinkedIn в этой итерации не проверялась; конкретные DOM-селекторы не фиксируются догадками.

## Два адаптера над общим исполнителем

| Capability — проектное имя | Результат | Внешнее изменение |
|---|---|---|
| `profile.read` | Версионированный снимок собственного профиля и полнота секций | Нет |
| `profile.diff` | Сверка HH, локального профиля и LinkedIn по полям | Нет |
| `profile.fill` | Перенос выбранной проверенной редакции в подходящую форму | Да, ввод данных; отдельно от сохранения |
| `profile.save` | Сохранение согласованных полей и чтение результата | Да |
| `jobs.recommended` | Карточки доступной рекомендованной выдачи | Нет |
| `jobs.detail` | Полный JD, источник, статус и данные Apply | Нет |
| `jobs.apply.open` | Переход к найденной форме/внешнему источнику | Навигация; без отправки |

Это будущие capabilities, **не текущие имена backend-команд или API endpoints**. Реальные имена определить при интеграции с existing `browser_commands` и worker protocol. Другие сайты реализуют только поддержанные capabilities; наличие adapter не означает универсальный submit.

Переиспользовать [навигацию](../../hh-research-extension/browser-navigation.js), [collection policy](../../src/collection_policy.py), [контракт импорта](../../src/collection_contract.py), [архив](../../src/archive_store.py), [задачи и прогресс](../architecture/application-layer.md), [дозагрузку](../architecture/hybrid-collection.md). Не заводить отдельную LinkedIn CRM, очередь или SQLite.

## Источники профиля и приоритеты

| Поле | Основа | Правило согласования |
|---|---|---|
| Title / Headline | Основное HH-CV, выбранное в локальном сервисе | Сопоставить смысл и ограничения поля LinkedIn; адаптацию показать отдельно |
| About | Проверенная локальная RU/EN-редакция, иначе HH About | Перевод и редактура сохраняют источник, язык и hash; без выдуманных достижений |
| Опыт | HH-снимок + подтверждённые локальные уточнения | Сопоставлять отдельные события, даты, роль и организацию, а не позицию в списке |
| Образование | Исходные записи HH/документы после проверки | Образование, курс и работа не взаимозаменяемы |
| Сертификаты | Именованные проверенные записи и credential URL | Issuer, ID, даты и срок действия сохраняются без догадок |
| Сайт | Разрешённая публичная проекция принятой редакции | Не зеркалить весь приватный профиль или трудовые документы |

Сейчас публичная проекция синхронизирует Title и опыт из HH, локальное введение и выбранные визуализации. Образование публичной страницы ещё берётся из `content/`. Его расширение и сертификаты должны войти в отдельную версию контракта, а не в незаметное расширение выгрузки.

Нужна сверка **трёх версий**: последнее согласованное состояние, новый локальный источник и фактический LinkedIn. Изменение только на LinkedIn сохраняется как конфликт/предложение, а не затирается. Смена основного CV, неполная секция или исчезнувшая карточка не означает разрешение удалить данные.

У каждого блока: стабильный локальный ID, platform/source ID при наличии, URL, язык, source version/hash, время наблюдения, степень полноты. Несколько должностей в одной компании, параллельные периоды, одинаковые курсы и неполные даты требуют явного сопоставления. Переводы — связанные редакции, не новая работа. Если нет перевода, показывать «Ожидается перевод»; генерация перевода — отдельный запрос или промпт без API.

## Сбор Jobs that match your profile

Начальная страница: [LinkedIn Jobs](https://www.linkedin.com/jobs/). Собирать доступный раздел рекомендаций из текущей авторизованной сессии владельца. Название раздела может зависеть от языка и интерфейса; adapter должен проверять признаки секции и доступность данных, а не один текст кнопки.

1. Проверить URL/сессию/тип страницы. Сохранить scope рекомендации, время и ссылку на наблюдавшийся снимок профиля, если он известен. Не обещать, что LinkedIn мгновенно пересчитал рекомендации после правки CV.
2. Собрать короткие карточки: platform job ID, канонический URL, title, компания, location/формат и доступный snippet. Поля зарплаты/даты могут отсутствовать; не выводить их из текста произвольно.
3. При прокрутке виртуализированного списка сохранять карточки по мере появления. Дедупликация по ID, checkpoint, лимиты времени/страниц/карточек, bounded ожидание новой порции и причина завершения обязательны.
4. Зафиксировать полноту: «доступная выдача до остановки», а не «все вакансии LinkedIn». CAPTCHA, login, лимит, смена layout и пустой непроверенный результат имеют отдельные причины.
5. Создать очередь только недостающих/устаревших деталей. Открывать карточку или detail URL, проверять job ID и дожидаться нужной области DOM. При split-pane убедиться, что описание действительно сменилось, а не принадлежит предыдущей карточке.
6. Сохранить полный текст с provenance/quality и Apply metadata; вернуть receipt. Прогресс показывать в расширении и веб-сервисе.

## Контракт вакансии и Apply

Следующие поля — проектные; перед миграцией согласовать их с существующими vacancy payload/identity и импортом:

| Группа | Минимальные данные |
|---|---|
| Identity | `source=linkedin`, `source_job_id`, `canonical_url`, существующий archive ID |
| Discovery | `collection_run_id`, scope, `first_seen`, `last_seen`, capture time, snippet |
| Detail | text, content hash, `description_quality`, extracted time, adapter version, причина неполноты |
| Apply | `apply_kind`: external / easy_apply / unknown; label, observed URL, target host, verified time |
| Provenance | Ссылка на исходную страницу, версия и receipt; связь с рекомендациями, но не cookies |

Внешний **Apply** может вести на ATS/сайт работодателя. Сохранять фактически найденный URL и каноническую ссылку вакансии раздельно. Разрешать только безопасные HTTP(S)-переходы; не исполнять `javascript:` и не переносить токены/идентификаторы сессии в архив или публичные экспорты. Redirect и конечный host требуют повторной проверки при открытии.

**Easy Apply** может быть кнопкой, открывающей форму внутри LinkedIn, без отдельного URL. В таком случае сохранить тип и ссылку вакансии как точку входа; не выдумывать прямую ссылку на форму. Не кликать кнопку с возможным submit-поведением ради извлечения URL. Неизвестное действие остаётся `unknown`.

Сбор/переход Apply не запускает отправку, загрузку CV или сообщений. Финальный сценарий отклика — отдельная capability с конкретным предпросмотром, существующими версиями и разрешением.

## Надёжность и хранение

- В SQLite сохраняются очередь, позиции, счётчики и receipts; большие JD не копируются в `chrome.storage.local` целиком.
- Resume повторно использует успешно сохранённые результаты. Receipt retry не повторяет действие. Полный свежий JD защищён от старой карточки.
- Пауза останавливает новые чтения на безопасной границе. Ошибка одной вакансии не откатывает успешные записи остальных.
- При login/CAPTCHA/access restriction — `needs_input`. Не передавать Chrome cookies в Python/GitHub Actions. Автоматического обхода ограничений доступа нет.
- Fallback возможен только между заявленными и проверенными способами чтения. Для приватных рекомендаций отсутствие session-adapter не компенсируется анонимным Python scraper.
- Модель не нужна для обычного чтения/сверки. Предлагаемые LLM-селекторы остаются отдельной [ограниченной recovery-системой](../ideas/llm-adapter-repair.md).

## Запись профиля

Пользовательский путь: **Прочитать LinkedIn → Сравнить с основным CV → Выбрать редакции → Предпросмотр → Применить → Проверить**.

Перед вводом повторно проверить собственный профиль, target URL, форму, исходные значения и версии. Согласование привязать к конкретному профилю, набору полей, base hash, patch hash и сроку. Не выполнять массовое «зеркалирование» с автоматическим удалением отсутствующих секций.

После сохранения перечитать поля и зафиксировать результат по каждому блоку: verified / conflict / needs_input / uncertain. Состояние uncertain требует сверки; слепого повторного save нет. Undo — новая проверенная редакция, а не обещание атомарного отката стороннего сайта. Чтение платформы не становится автоматически новой истиной для HH и не запускает цикл взаимных перезаписей.

## Приёмка

1. Fixtures реальных разрешённых страниц: RU/EN, collapsed/expanded секции, виртуализированная выдача, смена выбранного job ID, login/CAPTCHA, неполный DOM, внешняя ссылка и Easy Apply без URL.
2. Unit/contract: canonical ID, дубли, freshness, поля Apply, лимиты, источники и редактирование конфликтов.
3. Очередь: 0/N и частичные результаты, service-worker restart, потеря receipt, pause/resume, transient/backoff, quota и потеря сессии.
4. Профиль: независимые изменения в HH/LinkedIn, одинаковые компании/роли, параллельные даты, образование ≠ сертификат, смена primary CV, отсутствие перевода.
5. Controlled live read: одна собственная сессия, ограниченная выборка; проверить текст и источники вручную. Реальные profile-save действия проверить отдельно на согласованной редакции.
6. Публичный экспорт: нет cookies, закрытых документов, job-application истории и индивидуальных оценок; принятую редакцию можно проверить на сайте после Pages deployment.

Готовность объявлять по capability и версии adapter. Пока эти проверки не завершены, кнопки должны показывать реальное состояние, а не «LinkedIn синхронизирован».
