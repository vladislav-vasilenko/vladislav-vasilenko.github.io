# LinkedIn: локальное управление через Chrome Extension

Обновлено 24.10.2026. Реализация: Chrome Extension (версия — в [README](../README.md)), раздел **LinkedIn** (`?view=linkedin`). Доступ к LinkedIn включается отдельно в настройках расширения. Пароли и cookies не передаются сервису.

## Возможности и проверка

| Возможность | Реализовано | Граница проверки |
|---|---|---|
| Собственный профиль | Подтверждённая ссылка, чтение секций, разворачивание доступных detail-ссылок, ограниченная прокрутка | Связь и четыре секции проверены в активной сессии. Заголовок дополнительно читается из вводного блока новой разметки. Блок, не найденный при прокрутке, не считается пустым; для About читается редактор только по наблюдаемой ссылке |
| Сравнение с HH | Кнопка «Сравнить / синхронизировать с HH», текущее основное HH-CV справа, локальное введение, блоки опыта и образование | Перенос заголовка/About и полей опыта из источника; даты, образование и credentials проверяются по конкретной форме |
| Формы профиля | Чтение открытого редактора, согласование полей, перенос, отдельное сохранение | Offline проверки неизвестной формы, изменённой версии, другого профиля и исключения секретных полей. Живое сохранение не выполнялось |
| Вакансии | Карточки, промежуточные checkpoints, выборочная очередь полных JD, Apply/Easy Apply metadata | Проверены карточки и полные тексты нескольких вакансий, включая внешние Workday URL. Полная выдача LinkedIn не обещается |
| Чаты | Список доступных диалогов и чтение выбранного thread, связь с вакансией, локальные заметки | Только чтение. Загруженная часть истории, без обещания всей переписки |
| Network | Контакты, входящие/отправленные приглашения, поиск, заметки, теги, follow-up и связь с вакансией | Локальное управление и сохранение проверены тестами |
| Внешнее действие с контактом | Подготовка конкретного Connect / Accept / Ignore / Withdraw / Remove, проверка контекста и одноразовый запуск | Только явно выбранный контакт. Неоднозначная кнопка блокирует операцию. Дополнительное окно LinkedIn завершается вручную после проверки. Живые приглашения не отправлялись |

## Пользовательский путь

1. Перезагрузить установленное расширение, открыть его настройки и включить LinkedIn.
2. В веб-сервисе → LinkedIn подтвердить ссылку собственного профиля. В Chrome должен быть выполнен вход именно в этот аккаунт.
3. Нажать «Прочитать профиль». Проверить доступность каждой секции, а не только общий статус команды.
4. Открыть «Сравнить / синхронизировать с HH». Источник — основное полное HH-резюме из локального архива; введение может использовать проверенную локальную редакцию, общую с портфолио.
5. В Chrome открыть конкретную форму LinkedIn: intro, About, опыт, образование, курс или сертификат. В сервисе прочитать форму, выбрать и проверить значения, перенести их. Сохранение выполняется отдельной кнопкой.
6. После сохранения перечитать профиль. Закрытие формы ещё не доказывает, что все поля действительно сохранились.

Смена источника после переноса требует новой сверки. Автоматического удаления отсутствующих в HH записей, перевода или массовой перезаписи всех секций нет. Вакансии и прочитанные сообщения не становятся автоматически новой версией HH-CV.

## Хранение и очередь

- [linkedin_workspace.py](../../src/linkedin_workspace.py): private snapshots, records, notes и receipts на общей локальной SQLite; команды — в существующей таблице `browser_commands`, namespace `linkedin.*`.
- [linkedin_routes.py](../../src/linkedin_routes.py): `/archive/linkedin`. UI-сессия может управлять задачами; claim, checkpoint, progress и result требуют кода подключённого расширения.
- [linkedin-worker.js](../../hh-research-extension/linkedin-worker.js): ограниченный исполнитель активной сессии, служебные вкладки и подтверждение собственного профиля.
- [linkedin-content.js](../../hh-research-extension/linkedin-content.js): DOM-adapters; неизвестная структура требует участия пользователя.
- [linkedin.js](../../archive-web/linkedin.js): четыре вкладки и история операций.

Служебные ID, настройки LinkedIn и временный receipt хранятся в **IndexedDB расширения**, вне квоты `chrome.storage.local/session`. Объёмные JD и профили после приёма остаются в SQLite. Потеря HTTP-подтверждения повторяет receipt, а не клик. После истечения lease внешняя запись становится `uncertain` и не исполняется повторно автоматически.

Списки сохраняются порциями во время прокрутки. Пауза/остановка работают на безопасной границе чтения. Частичное наблюдение не означает отсутствия остальных контактов, вакансий или сообщений. Аккаунты разделены; смена профиля отменяет ожидающие команды прежнего аккаунта.

История чатов, контакты, заметки и внутренние snapshots LinkedIn не попадают в публичную HH-проекцию портфолио или GitHub Actions. Никаких вызовов LLM для обычного чтения, сравнения и переноса нет.

## Оставшиеся проверки

- Проверка всех секций и редакторов RU/EN в текущей разметке аккаунта.
- Контрольный profile-save на отдельно согласованных значениях.
- Проверка конкретных network-действий на отдельно согласованных контактах.
- Дополнительные fixtures виртуализированных списков, длинных threads и новых вариантов редакторов.

При частичном чтении сохраняется доступный снимок. Не распознанный заголовок требует проверки, UI не объявляет все блоки синхронизированными. HH-источник свёрнут по умолчанию, при сравнении показывается справа без дублирования вводного текста.

## Обновление 24.10.2026 · 0.12.2

- Секции профиля ограничиваются собственным контейнером или диапазоном до следующего заголовка. Пустые повторяющиеся ссылки treasury/skills исключаются; записи опыта и образования показываются отдельно.
- По умолчанию включена галочка **«Собирать с полными описаниями»**. Три источника рекомендаций: preferences, profile, more. Infinite scroll и pagination — варианты обхода одной подборки, а не разные источники. `origin=INFINITE_JOBS_LANDING` относится к more, `QUALIFICATION_LANDING` — к profile. Пересечения объединяются по LinkedIn ID.
- Карточки без href читаются через фактический выбор карточки и URL выбранной вакансии. На главной используется прокрутка нижней границы; в полной выдаче — прокрутка списка и Next/номера страниц. Полнота выдачи не гарантируется.
- Максимум запуска — 500 карточек. Checkpoints передаются до 50 записей, финал подтверждает список сохранённых URL. Полные JD идут отдельными командами. Импорт в основной архив — явная кнопка, порции до 100. Большой список не передаётся одним многомегабайтным пакетом.
- SQLite хранит случайно выбранную цель каждой порции (по умолчанию 8–12), счётчик, случайный интервал каждой загрузки (3–8 секунд), следующий допустимый момент и перерыв между порциями (60 секунд). Диапазоны настраиваются. Состояние не пересчитывается при каждом poll; повтор результата не расходует дополнительное место. Паузы касаются индивидуального чтения карточек и полных JD; уже видимые карточки одной страницы могут быть сохранены одним checkpoint.
- Worker сохраняет связь во время перерыва и восстанавливает ожидание по SQLite. При истечении lease сохраняется прочитанная часть, задача требует проверки; автоматического продолжения прерванной страницы с полной гарантией нет.
- При запросе входа/ручной проверки очередь останавливается. Случайные интервалы не гарантируют незаметность или отсутствие ограничений аккаунта. Fingerprint spoofing, автоматическое решение CAPTCHA и обход блокировок не реализованы.
- Новый DOM полного JD может догружаться только после реального открытия вкладки: worker ограниченно ждёт, прокручивает, при необходимости активирует вкладку и возвращает прежнюю, если пользователь не переключился сам. Проверены полные тексты нескольких разных вакансий, Easy Apply и внешние Workday URL. Плашка Full-time больше не используется как название вакансии.
- Сохраняются локации, логотип с разрешённого LinkedIn CDN, исходная относительная дата, число кандидатов с признаком нижней границы, зарплата/формат/занятость, Viewed, Promoted, early applicant, actively reviewing, school alumni. Viewed не означает просмотр отклика работодателем. Относительная дата не превращается в выдуманный точный `pub_date`.
- В чатах/контактах сохраняются видимые badges, непрочитанность, подпись времени, общие контакты и аватар. Полнота длинных threads и новых вариантов DOM требует отдельной живой проверки.
- [Команды и стримы](../architecture/vacancy-teams.md) размещены в основном разделе вакансий. Источники LinkedIn/Hugging Face разделены; членство не приравнивается к подтверждённой роли.

Правила платформы: [Automated activity on LinkedIn](https://www.linkedin.com/help/linkedin/answer/a1341543). Темп чтения служит управлению очередью, а не обещанию обхода ограничений.


## Чаты и сервис контактов · 0.12.4

Вкладка **Чаты** обходит список диалогов прокруткой вниз и выбирает реальные карточки разговоров. Флажок «Открыть каждый чат и загрузить сообщения» создаёт отдельные задачи чтения истории; список и история имеют независимые границы. История дозагружается прокруткой вверх, сообщения объединяются по ID. Поддерживаются thread ID с Base64-паддингом `==`. В контекст не включается вся страница Messaging.

Новая панель **«Анализ чатов и рекомендации»** выбирает до 30 диалогов, полное резюме, карьерную цель и траекторию. Она показывает объём подготовленного контекста до API-вызова. Luna, Terra и Sol используют существующий конфиг моделей. Режим без API копирует промпт и принимает JSON результата; платный вызов выполняется только отдельной кнопкой с подтверждением выбранных данных. Повторное чтение готового результата использует локальный кэш. См. [контракт анализа](linkedin-chat-advice.md).

Вкладка **Контакты** содержит сервис сбора списка Connections и входящих/отправленных приглашений. Сбор ограничивается выбранным максимумом 1–300 за запуск, сохраняется checkpoints и продолжается прокруткой вниз. Для ленивой загрузки Connections расширение показывает служебную вкладку и возвращает предыдущую, если пользователь не переключился сам. Кнопка «Дособрать новые» пропускает уже сохранённые профили из выбранного списка и продолжает прокрутку, поэтому повторный запуск не ограничивается одними и теми же первыми контактами. Максимум прохода не ограничивает общий объём базы.

Поиск, фильтр по прочитанному списку и страницы по 40 записей работают по всей локальной коллекции, включая записи за пределами обзорного ответа. Ключ — аккаунт и канонический профиль LinkedIn. Повторное чтение не создаёт дубль и не стирает заметки либо более полные должность/компанию/локацию. Сохраняются дата первого/последнего наблюдения, список источников наблюдения, доступные бейджи, степень связи и общие контакты. Компания сохраняется отдельным полем только по наблюдаемой ссылке компании внутри карточки. Фраза вроде «Delivery at Scale» не превращается в компанию Scale. Исходный headline сохраняется; роли в команде по знакомству не выводятся.

Сбор — чтение. Действия Connect/Accept/Ignore/Withdraw/Remove остаются в свёрнутом блоке для конкретного контакта и требуют отдельного предпросмотра. API поиска: `POST /archive/linkedin`, `op=contacts`, поля `query`, `scope`, `offset`, `limit`. Аккаунты разделены. Источник первого этапа — LinkedIn; адаптер Setka ещё не подключён.

Живая проверка 24.10.2026: собрано **25 контактов**, включая дозагрузку после исходных 10. Отправки сообщений и приглашений при проверке не выполнялись.

Живая проверка чатов: прочитаны **3 диалога и 9 сообщений** (1, 2 и 6), подготовлен локальный контекст на 3 диалога. Платных попыток анализа: **0**. Кнопка копирования прошла UI-путь без API; системный буфер IAB требует отдельной проверки в пользовательском Chrome.


Проверенные 25 контактов и 3 диалога прочитаны загруженным worker 0.12.3. Финальные исходники 0.12.4 добавляют дозагрузку новых контактов, очистку превью и строгий источник компании; после обновления нужно перезагрузить установленное расширение. Команда `only_new` не выдаётся старому worker как обычный повторный сбор.

Проверка навигации: infinite scroll собрал **80 уникальных вакансий** в активной сессии. Повторная проверка pagination остановилась на 25 карточках; Mac был заблокирован, и следующий переход не удалось проверить в Chrome. Offline fixtures проходят 80 карточек через четыре страницы, но не заменяют эту живую проверку. До продолжения нельзя заявлять живую проверку 70+ через pagination завершённой.
