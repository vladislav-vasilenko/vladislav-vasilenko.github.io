# Telegram: расписание и очередь действий

Обновлено 24.10.2026. Состояние хранится в локальной SQLite; публикации приватных данных в GitHub нет.

## Роль Telegram

Раздел «Сегодня» и CRM — источник состояния. Telegram — дополнительный интерфейс и доставка напоминаний. Scheduler работает в локальном сервисе независимо от long polling бота; общий lease предотвращает одновременное продвижение двумя процессами. Для доставки должны работать сервис/бот и сеть; спящий компьютер не отправляет уведомления.

Основной режим `tasks`: в существующие интервалы `TELEGRAM_DIGEST_TIMES` (по умолчанию 10:00, 19:00, `Europe/Moscow`) присылать одну компактную очередь. Настройка доступна в «Сегодня → Управление поиском → Напоминания Telegram», сохраняется через `notification_config_save` в `settings.telegram_notifications`. Другие режимы: `both`, `discovery`, `off`. Режим `off` выключает плановые подборки и обзоры проверок; явные follow-up, интервью, новые сообщения HH и события задач остаются отдельными уведомлениями. Эта настройка не меняет GitHub Actions или автосинхронизацию HH.

В очереди: письмо, ожидающее следующего шага; `needs_input`, `needs_approval`, `fields_filled`, `uncertain`; наступивший CRM follow-up. Проверки не ограничены текущим CV: начатый отклик со старым выбранным резюме тоже требует внимания. `fields_filled` означает перенос текста, а не отправку. Завершённые/отклонённые/отозванные кейсы, оффер, `work_status=done`, дочерние каналы и заменённые контексты исключаются. Будущий follow-up откладывает плановое напоминание, не скрывая саму карточку в интерфейсе.

Пустая очередь молчит. Одна запись outbox на интервал, максимум восемь карточок с кнопками; остальные доступны в списке. После сна учитывается только последний интервал моложе четырёх часов. Перед доставкой заново читается состояние: исчезнувшие задачи убираются, актуальные тексты обновляются, просроченная доставка отменяется. Неоднозначный результат Telegram остаётся `uncertain` и автоматически не повторяется. Это не расписание облачного сервера и не гарантия доставки в точную минуту.

## Проверка прежних рекомендаций

В аудите локального архива последние четыре scheduled run завершились `needs_embeddings` / `needs_input`. Прежнее завершение поиска могло при этом рассылать общий сохранённый рейтинг, не проверяя свежесть. Также начатые подготовки не исключались, а дневной dedupe искал ключи другого формата. Поэтому прежнее расписание нельзя было считать гарантией актуальной подборки.

При явном включении плановых вакансий теперь требуется завершённый поиск, ID из этого запуска, полный неизменённый текст, проверка доступности не старше 30 минут, описание не старше суток и текущий рейтинг относительно CV/цели. Старые сохранённые рекомендации после неудачного обновления не подставляются. Начатые кейсы, отмеченные отклики и «Не моё» исключаются. Дневной dedupe поддерживает текущие и прежние ключи. Скрытого ограничения «Москва/remote» больше нет — география задаётся условиями поиска. Перед фактической доставкой актуальность проверяется снова. Рейтинг по запросу остаётся доступен и явно обозначается как сохранённый; он не подтверждает текущую активность вакансий.

## Проверка изменений

[Тесты политики](../../src/tests/test_career_notifications.py): временная SQLite, подменённый транспорт, ни одного реального сообщения или вызова модели. Проверены повторы, перезапуск, второй интервал, устаревшая очередь, завершение/отложенное действие, заполненная форма, авторизация API, ручной поиск при режиме `tasks`, исключение подготовки, оба формата ключей, отказ от старого рейтинга после ошибки обновления. [UI-тесты](../../hh-research-extension/today-ui.test.mjs) проверяют общий фокус действий и настройку режима.
